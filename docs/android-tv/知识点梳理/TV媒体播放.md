### Android TV 媒体播放知识点清单

###### 内容概述

本文件记录 Android TV 媒体播放相关知识，包括播放器选型、Media3/ExoPlayer、播放状态、遥控器控制、音频焦点、字幕、清晰度、播放页焦点和错误处理。

###### 使用场景

- TV 视频、直播、短视频、教育课程、音频和大屏播放场景都需要媒体播放能力。
- 播放页遥控器控制、焦点层级、控制栏显示隐藏、断网重试、清晰度切换都可以从本文件梳理。
- 面试中常会问播放器状态、音频焦点、播放错误、遥控器控制和 ExoPlayer / Media3 使用经验。

<a id="播放器选型"></a>
###### 播放器选型

- Android 视频播放常见选择是 Media3/ExoPlayer、系统 MediaPlayer、厂商播放器或自研播放器。
- 新项目通常优先考虑 Media3/ExoPlayer，因为它能力完整、可扩展性强，支持 DASH、HLS、SmoothStreaming、字幕、轨道选择等。
- 系统 MediaPlayer API 简单，但扩展能力、格式支持、状态控制和错误处理不如 ExoPlayer 灵活。
- 如果项目涉及 DRM、直播低延迟、厂商硬解、特殊格式或业务强定制，可能需要播放器 SDK 或厂商方案。
- 选型要看：格式支持、直播/点播、清晰度切换、字幕、缓存、DRM、错误重试、埋点、性能、设备兼容。

<a id="播放状态"></a>
###### 播放状态

- 播放器状态管理要明确区分：初始化、准备中、播放中、暂停、缓冲、播放完成、播放失败、释放。
- UI 状态要跟随播放器状态变化，例如 loading、播放按钮、进度条、错误页、重试按钮。
- 缓冲状态不等于暂停。缓冲是播放器等待数据，暂停是用户或业务主动停止播放推进。
- 播放完成后要根据业务决定：自动播放下一集、停在结束页、显示推荐、回到详情页。
- 直播和点播的状态处理不同。直播通常没有固定 duration，进度条、回看、时移和追帧逻辑要单独处理。
- 播放器状态、页面生命周期和业务状态要分层，不要把所有逻辑写进 Activity。

<a id="遥控器控制"></a>
###### 遥控器控制

- 播放页要支持遥控器确认键、返回键、播放暂停键、左右方向键、上下方向键。
- 常见设计：

| 按键 | 常见行为 |
|---|---|
| 确认键 | 显示控制层或执行当前焦点按钮 |
| 返回键 | 先隐藏控制层，再退出播放页 |
| 左 / 右 | 控制层显示时切换焦点；隐藏时可快退 / 快进 |
| 上 / 下 | 显示控制层、切换清晰度/选集/字幕入口 |
| 播放暂停键 | 切换播放和暂停 |

- 控制层隐藏时，方向键是先显示控制层还是直接快进，要按产品交互统一。
- 播放页不要让方向键无响应。即使不处理，也要给用户明确反馈或显示控制层。
- 快进快退要处理长按和连续按键，避免每次按键都触发重型 seek。
- 遥控器确认键要同时考虑 `DPAD_CENTER` 和 `ENTER`。

<a id="播放页焦点"></a>
###### 播放页焦点

- 播放页通常有视频层、控制层、选集浮层、清晰度浮层、字幕浮层、错误页等多层焦点。
- 控制层显示时，焦点应进入控制层的默认按钮，例如播放暂停按钮或进度条附近按钮。
- 控制层隐藏时，要避免焦点落到不可见按钮上。可以把焦点交给播放根容器，或者在下次显示控制层时恢复上次焦点。
- 弹出选集、清晰度、字幕面板时，焦点应进入面板内当前选中项。
- 面板关闭后，焦点应回到打开面板的入口按钮。
- 错误页显示时，重试按钮或返回按钮要自动获得焦点。
- 播放器焦点层级要有明确优先级：错误页 > 弹窗/面板 > 控制层 > 视频根容器。

<a id="音频焦点"></a>
###### 音频焦点

- 音频焦点用于协调多个应用或系统声音之间的播放权。
- 视频播放开始前通常要请求音频焦点，失去音频焦点时根据类型暂停、降低音量或停止。
- 短暂失去焦点可以暂停或降低音量，永久失去焦点通常应停止播放或释放资源。
- TV 场景还要考虑系统语音助手、蓝牙音箱、HDMI 设备、系统提示音等影响。
- 音频焦点处理不当会导致和其他应用抢声音、后台还在播放、切回后声音异常。

<a id="字幕和清晰度"></a>
###### 字幕和清晰度

- 字幕要考虑字体大小、颜色、边框、阴影、位置和背景对比，保证远距离可读。
- 字幕不能太靠屏幕边缘，避免被电视裁切或系统浮层遮挡。
- 清晰度切换要处理当前播放进度、缓冲状态、失败回退和用户选择记忆。
- 多音轨、多字幕、多清晰度都可以理解为轨道选择问题。
- 清晰度切换后要明确 UI 反馈，例如“正在切换”“已切换到 1080P”“切换失败”。
- 直播场景的清晰度切换和点播不同，可能涉及重新拉流和追帧。

<a id="错误处理"></a>
###### 错误处理

- 播放错误要区分网络错误、资源不存在、格式不支持、解码失败、DRM 授权失败、服务器错误、超时等。
- 错误页要提供可操作入口，例如重试、切换清晰度、返回详情页、检查网络。
- 不要只展示错误码。错误码可以给开发和客服，但用户需要看得懂的提示。
- 弱网场景要处理缓冲超时、断网重连、网络恢复后继续播放。
- 播放错误要打点，至少记录播放地址类型、清晰度、错误码、设备信息、网络状态、播放器状态。
- 设备兼容问题要保留机型、系统版本、解码器、视频编码格式等信息。

<a id="生命周期"></a>
###### 生命周期

- 页面进入时初始化播放器，页面退出时释放播放器，前后台切换时按业务暂停或继续。
- 按 Home 键、屏保、系统休眠、来电/语音助手、HDMI 切换等场景都可能影响播放。
- Activity/Fragment 生命周期和播放器生命周期不要混在一起，建议封装播放控制器或播放状态管理层。
- 播放进度要按业务保存，例如退出播放页时保存观看进度，返回详情页后展示继续观看。
- 释放播放器时要取消回调、移除监听、停止计时器，避免内存泄漏。
