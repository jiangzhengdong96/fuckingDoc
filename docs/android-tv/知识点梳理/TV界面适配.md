### Android TV 界面适配知识点清单

###### 内容概述

本文件记录 Android TV 界面适配知识，包括大屏布局、视觉层级、安全区域、焦点态、卡片设计、文字图片适配、状态反馈和无障碍注意点。

###### 使用场景

- 设计 TV 首页、详情页、搜索页、播放器控制层和设置页时，用于检查大屏界面是否适合遥控器操作。
- 从手机端 UI 迁移到 TV 端时，用于判断布局、字体、按钮、导航和焦点态需要如何调整。
- 排查用户看不清、焦点不明显、元素过密、列表抖动等体验问题时，用于定位 UI 层原因。

<a id="大屏布局"></a>
###### 大屏布局

- TV 端通常是横屏大屏，布局应优先适配 16:9 场景。
- TV 端用户距离屏幕较远，信息密度要比手机端低。不要把手机端的密集列表、细小按钮直接放大。
- 页面应突出主内容区，减少复杂顶部栏、底部栏和多层菜单。
- 常见 TV 页面结构：

| 页面 | 常见结构 |
|---|---|
| 首页 | 顶部导航 + Banner + 多行内容卡片 |
| 详情页 | 背景图 / 海报 + 标题信息 + 操作按钮 + 推荐列表 |
| 搜索页 | 输入区 + 热门词 + 结果列表 |
| 播放页 | 视频层 + 控制层 + 选集 / 清晰度 / 字幕浮层 |
| 设置页 | 左侧菜单 + 右侧配置内容 |

- TV 端要优先减少页面跳转层级。遥控器输入成本高，多层页面会让用户迷失。
- 操作路径要符合方向键直觉：横向栏目左右移动，列表上下切换行，返回键返回上一层。

<a id="安全区域"></a>
###### 安全区域

- 不同电视、盒子、投影可能存在缩放、边缘裁切或 overscan 问题，边缘内容不要贴边。
- 重要信息和可操作控件要放在安全区域内，避免在部分设备上被裁掉。
- 页面左右和上下应保留足够边距，尤其是导航、按钮、字幕、播放控制条等关键元素。
- 背景图可以铺满屏幕，但标题、按钮、焦点卡片不要放到最边缘。
- 如果目标设备存在系统导航栏、状态栏、厂商悬浮层，要额外验证沉浸式和非沉浸式效果。

<a id="视觉层级"></a>
###### 视觉层级

- TV 页面通常要让用户一眼知道：当前在哪个页面、当前焦点在哪、下一步能做什么。
- 视觉层级可以通过字号、颜色、空间、背景、阴影、卡片大小建立。
- 焦点元素应明显高于非焦点元素，可以用放大、边框、阴影、亮度、Z 轴层级表达。
- 次要信息要弱化，避免和焦点元素抢视觉注意力。
- 背景图不要影响前景文字可读性。必要时增加遮罩、渐变暗化或局部背景。
- TV 不适合大量小图标和弱对比文字。远距离下低对比和小字号会非常难读。

<a id="焦点态设计"></a>
###### 焦点态设计

- 焦点态是 TV UI 的核心状态，至少要让用户明确知道当前焦点在哪。
- 常见焦点态方式：

| 方式 | 说明 |
|---|---|
| 放大 | 当前卡片略微放大，常用于内容卡片 |
| 描边 | 当前按钮或卡片增加高亮边框 |
| 阴影 | 当前卡片浮起，增强层级 |
| 背景变化 | 当前菜单或按钮改变背景色 |
| 文案变化 | 当前项文字加粗或变亮 |

- 焦点放大时要预留空间，避免放大后遮挡旁边卡片或触发布局抖动。
- 焦点态动画要短、稳定、可预期。动画过长会让用户连续按键时感觉卡顿。
- 焦点态不要只靠颜色区分，最好叠加大小、描边或阴影，降低不同屏幕显示差异影响。
- 禁用态、选中态、焦点态要区分开。选中的 Tab 不一定是当前焦点；当前焦点也不一定是业务选中项。

<a id="卡片和列表"></a>
###### 卡片和列表

- 卡片是 TV 首页和内容流最常见的内容单元。
- 卡片尺寸要稳定，图片加载前后不要改变宽高，避免焦点位置跳动。
- 卡片之间要保留足够间距，给焦点放大和阴影留空间。
- 卡片文案要短，长标题可以单行省略或两行省略，不要撑开 item 高度。
- 海报比例、横图比例、方图比例要统一管理，不要在同一行混用太多比例。
- 列表行标题、更多按钮、内容卡片之间要有明确焦点路径。
- 如果页面存在“更多”入口，要考虑从最后一个卡片向右时是进入更多，还是保持在当前行。

<a id="文字和图片"></a>
###### 文字和图片

- 字体大小要考虑观看距离。正文、按钮、角标、标签都要在真实电视上验证可读性。
- 文案要尽量短。TV 上长说明文字阅读成本高。
- 图片要有占位图、错误图和加载状态，避免空白区域让用户以为页面坏了。
- 图片加载要控制尺寸，避免加载远大于显示尺寸的原图造成内存浪费。
- 背景图要注意亮度和对比，前景文字需要有可读性保护。
- 播放页字幕、清晰度、进度、错误提示要避免和系统安全区域、厂商浮层冲突。

<a id="状态反馈"></a>
###### 状态反馈

- 遥控器操作后要有及时反馈。比如按确认键后按钮状态变化、加载中、Toast、弹窗或页面跳转。
- 加载态要给出焦点处理策略。加载期间焦点留在原按钮、给 loading 容器、还是禁用操作，要明确。
- 空态要可操作，例如重试按钮、返回按钮、刷新按钮，而不是只有一段说明文字。
- 错误态要能用遥控器恢复，例如网络错误页的“重试”按钮要自动获得焦点。
- 播放页错误提示要给出下一步：重试、切换线路、返回详情、联系客服或查看网络。

<a id="无障碍和可读性"></a>
###### 无障碍和可读性

- TV 上也要考虑无障碍描述，尤其是按钮、图片按钮、播放控制按钮。
- 图标按钮要有清晰语义，不要只显示难懂图标。
- 遥控器可达性很重要。所有可操作入口都应该能通过方向键到达。
- 不要让焦点陷入某个区域出不来，除非这是弹窗或明确的模态场景。
- 文本和背景对比度要足够，避免不同电视色彩模式下难以阅读。
