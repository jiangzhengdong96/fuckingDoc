<a id="tv-ui-适配和手机-ui-适配有什么区别"></a>
###### TV UI 适配和手机 UI 适配有什么区别

答案：

**简答：** TV UI 面向远距离观看和遥控器操作，手机 UI 面向近距离触摸操作。

**展开回答：** TV UI 字体、间距、卡片和焦点态要更明显，信息密度要更低，布局以横屏大屏为主。用户不能直接触摸控件，所以每个入口都要能通过方向键到达。页面层级要更短，焦点路径要清晰。

**易错点：** 不能简单把手机 UI 放大后搬到 TV 上。

**关联知识点：** [大屏布局](../知识点梳理/TV界面适配.md#大屏布局)

<a id="tv-焦点态应该怎么设计"></a>
###### TV 焦点态应该怎么设计

答案：

**简答：** 焦点态要明显、稳定、远距离可见，并且不能引发布局抖动。

**展开回答：** 常见方式包括放大、描边、阴影、背景变化、文字变亮。焦点放大要预留空间，避免遮挡或挤动周围元素。焦点态、选中态、禁用态要区分开。动画时间要短，连续按键时不能拖慢操作。

**易错点：** 只靠颜色变化不够可靠，不同电视显示效果差异可能让焦点不明显。

**关联知识点：** [焦点态设计](../知识点梳理/TV界面适配.md#焦点态设计)

<a id="tv-为什么要考虑安全区域"></a>
###### TV 为什么要考虑安全区域

答案：

**简答：** 因为不同电视和盒子可能有缩放、裁切、系统浮层，边缘内容可能显示不完整。

**展开回答：** 重要文案、按钮、字幕、控制条不要贴边。背景图可以铺满，但关键操作要留在安全区域内。发布前要在真实设备上验证边缘裁切和系统显示差异。

**易错点：** 模拟器上正常不代表真实电视上边缘也正常。

**关联知识点：** [安全区域](../知识点梳理/TV界面适配.md#安全区域)

<a id="tv-卡片列表设计要注意什么"></a>
###### TV 卡片列表设计要注意什么

答案：

**简答：** 卡片尺寸要稳定，焦点态要清晰，间距要足够，图片和标题不能导致 item 尺寸变化。

**展开回答：** TV 首页通常大量使用卡片列表。卡片要有固定比例、占位图、错误图和清晰标题。焦点放大要预留空间，避免遮挡和抖动。长标题要省略，图片加载不能改变布局尺寸。

**易错点：** 卡片焦点放大如果参与布局测量，可能导致列表抖动和焦点错乱。

**关联知识点：** [卡片和列表](../知识点梳理/TV界面适配.md#卡片和列表)

<a id="tv-列表卡顿怎么优化"></a>
###### TV 列表卡顿怎么优化

答案：

**简答：** 从刷新、布局、图片、焦点动画、主线程任务和设备性能几个方向定位。

**展开回答：** 刷新上用 DiffUtil 和局部刷新，避免全量 notify。布局上固定 item 尺寸、减少层级。图片按显示尺寸加载，避免大图解码。焦点动画不要触发布局。数据转换、排序和过滤放后台线程。嵌套 RecyclerView 可以考虑共享 ViewPool、合理缓存和预加载。

**易错点：** 不要只优化代码局部，要结合 Profiler、日志、帧耗时、GC 和真机表现定位瓶颈。

**关联知识点：** [性能优化](../知识点梳理/TV列表和焦点性能.md#性能优化)
