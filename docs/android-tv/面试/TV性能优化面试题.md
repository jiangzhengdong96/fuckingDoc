<a id="tv-端性能优化和手机端有什么不同"></a>
###### TV 端性能优化和手机端有什么不同

答案：

**简答：** TV 端更关注遥控器连续按键响应、焦点移动稳定、横屏大图列表、播放稳定性和低端设备兼容；手机端更偏触摸滑动、页面切换和多分辨率适配。

**展开回答：** TV 应用常见场景是首页推荐流、横竖嵌套列表、详情页、播放页。用户会连续按方向键快速移动焦点，如果焦点动画、列表滚动、图片解码和数据刷新同时发生，就容易出现卡顿、焦点丢失或按键无响应。TV 设备硬件差异很大，低端盒子 CPU、GPU、内存和存储都可能偏弱，所以不能只在高性能设备上验证。

**易错点：** TV 端性能不是只看 FPS，还要看按键响应、焦点是否稳定、首屏是否可操作、播放是否平稳。

**关联知识点：** [TV 列表和焦点性能 - 性能优化](../知识点梳理/TV列表和焦点性能.md#性能优化)

<a id="tv-首页列表卡顿怎么排查"></a>
###### TV 首页列表卡顿怎么排查

答案：

**简答：** 先区分卡顿发生在数据刷新、ViewHolder 创建、布局测量、图片加载、焦点动画还是主线程耗时，再结合日志、Profiler、帧率和实际按键路径定位。

**展开回答：** 排查首页列表卡顿可以按顺序看：是否用了 `notifyDataSetChanged()` 全量刷新；item 布局是否层级过深；图片是否按显示尺寸加载；是否每次焦点变化都创建动画对象；横竖嵌套列表是否共享 `RecycledViewPool`；是否在主线程做排序、过滤、JSON 解析或图片处理。连续按方向键是必须压测的场景，因为它最容易暴露滚动、焦点和图片加载之间的竞争。

**易错点：** 只优化网络请求不一定能解决列表卡顿，很多卡顿来自主线程布局、图片解码和焦点动画。

**关联知识点：** [TV 列表和焦点性能 - 性能优化](../知识点梳理/TV列表和焦点性能.md#性能优化)

<a id="tv-横竖嵌套列表怎么优化"></a>
###### TV 横竖嵌套列表怎么优化

答案：

**简答：** 外层竖向列表和内层横向列表要减少 ViewHolder 创建、保持 item 身份稳定、保存滚动和焦点位置，并控制图片加载和预加载范围。

**展开回答：** TV 首页常见结构是外层栏目列表加内层内容列表。优化重点包括：内层 RecyclerView 共享 `RecycledViewPool`；使用 `ListAdapter + DiffUtil`；开启 stable id；保存栏目 id 和内容 id 用于焦点恢复；固定 item 尺寸；关闭不必要的 `ItemAnimator`；图片按尺寸加载；避免每行重复创建重资源对象。

**易错点：** 只保存 position 不够，数据刷新、推荐位变化或内容下架后 position 可能指向错误内容，应该优先保存业务 id。

**关联知识点：** [TV 列表和焦点性能 - 横竖嵌套列表](../知识点梳理/TV列表和焦点性能.md#横竖嵌套列表)

<a id="焦点动画导致卡顿怎么处理"></a>
###### 焦点动画导致卡顿怎么处理

答案：

**简答：** 焦点动画要轻量、可复用、避免触发布局，尽量使用 `scale`、`alpha`、阴影或边框状态，不要在焦点变化时频繁改变 item 尺寸或创建复杂动画。

**展开回答：** TV 焦点态通常会放大卡片、显示边框或阴影。如果动画改变了布局尺寸，RecyclerView 可能重新测量和布局，连续按键时就容易卡顿。更稳的做法是外层容器固定尺寸，内部内容做 `scaleX/scaleY`，并给放大留出空间，避免被父容器裁剪。动画时长要短，状态切换要可取消，避免多个动画叠加。

**易错点：** 焦点放大不是越明显越好，过重的阴影、模糊和大图裁剪在低端 TV 上很容易掉帧。

**关联知识点：** [TV 列表和焦点性能 - 焦点稳定](../知识点梳理/TV列表和焦点性能.md#焦点稳定)

<a id="tv-图片加载怎么优化"></a>
###### TV 图片加载怎么优化

答案：

**简答：** 按显示尺寸加载图片，固定 item 宽高，使用占位图和缓存，控制预加载范围，避免原图解码、复杂变换和快速滚动时的错图。

**展开回答：** TV 首页海报和背景图很多，图片加载会直接影响滚动和内存。item 应有固定尺寸，避免图片加载完成后撑开布局。图片库要按目标尺寸 decode，不要加载原图后再缩小。快速移动焦点时，要避免旧请求回调设置到复用后的 ViewHolder。背景大图要控制加载时机，避免焦点快速移动时连续解码大图。

**易错点：** 大图、圆角、阴影、模糊、渐变叠加在一起，可能比列表逻辑本身更消耗性能。

**关联知识点：** [TV 列表和焦点性能 - 图片加载](../知识点梳理/TV列表和焦点性能.md#图片加载)

<a id="tv-播放页性能要关注什么"></a>
###### TV 播放页性能要关注什么

答案：

**简答：** 播放页要关注起播速度、卡顿率、缓冲、清晰度切换、控制层响应、字幕、焦点路径和播放状态恢复。

**展开回答：** TV 播放页通常是核心页面，性能不只是 UI 帧率，还包括播放器准备耗时、弱网缓冲、解码能力、音频焦点、控制层显示隐藏、遥控器按键响应和返回恢复。控制层 UI 不应频繁重建，进度更新要控制频率，字幕和清晰度列表要保证焦点可操作。播放页还要处理进入后台、熄屏、HDMI 切换、网络变化等状态。

**易错点：** 播放页性能优化不能只看 ExoPlayer 或 Media3，还要看控制层 UI、焦点、网络和设备解码能力。

**关联知识点：** [TV 媒体播放](../知识点梳理/TV媒体播放.md)

<a id="tv-端内存优化怎么做"></a>
###### TV 端内存优化怎么做

答案：

**简答：** 控制图片尺寸和缓存，避免 Activity / Fragment 泄漏，释放播放器和大图资源，控制列表缓存规模，并关注低端设备内存压力。

**展开回答：** TV 应用大量使用海报、背景图、播放器和推荐列表，内存上涨很常见。优化时要检查图片是否按尺寸加载，背景图是否重复持有，播放器是否在页面销毁时释放，Adapter 或回调是否持有旧页面，缓存是否无上限。嵌套列表不要盲目把缓存调很大，缓存过多会换来内存压力。

**易错点：** TV 屏幕大不代表可以加载更大原图，显示尺寸和设备内存才是关键。

**关联知识点：** [TV 列表和焦点性能 - 预加载和缓存](../知识点梳理/TV列表和焦点性能.md#预加载和缓存)

<a id="tv-性能问题常用哪些排查工具"></a>
###### TV 性能问题常用哪些排查工具

答案：

**简答：** 常用 Logcat、Android Studio Profiler、Layout Inspector、帧率观察、`adb shell dumpsys gfxinfo`、Perfetto/Systrace、播放器日志和真机按键压测。

**展开回答：** UI 卡顿可以看帧耗时、布局层级、主线程调用栈；内存问题看 heap、图片缓存和对象引用；播放问题看播放器事件、缓冲、码率和解码日志；焦点问题看 `findFocus()`、按键分发日志和焦点变化日志。TV 性能排查必须结合遥控器连续按键，因为真实用户操作方式和手机滑动不同。

**易错点：** 模拟器或高性能盒子通过不代表低端真机通过，TV 性能要覆盖多设备验证。

**关联知识点：** [TV 发布和调试](../知识点梳理/TV发布和调试.md)
