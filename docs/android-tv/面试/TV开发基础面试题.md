<a id="android-tv-和手机-app-开发有什么区别"></a>
###### Android TV 和手机 App 开发有什么区别

答案：

**简答：** TV 端以遥控器和焦点为核心，手机端以触摸为核心。TV 还要关注大屏远距离观看、横屏布局、焦点路径、按键响应、播放和设备兼容。

**展开回答：** 手机端用户可以直接点击任意控件，TV 端用户必须先把焦点移动到控件上再确认。TV 端信息密度要更低，焦点态要更明显，页面路径要更短。列表和播放器是 TV 高频场景，焦点丢失、焦点错乱、按键无响应、列表卡顿都比手机端更突出。

**易错点：** 不能把 TV 简单当成横屏手机。TV 端要先设计焦点路径，再写页面。

**关联知识点：** [TV 和手机端差异](../知识点梳理/TV开发基础.md#tv-和手机端差异)

<a id="什么是-10-foot-ui"></a>
###### 什么是 10-foot UI

答案：

**简答：** 10-foot UI 是适合用户远距离观看和操作的界面设计方式，典型场景就是电视。

**展开回答：** 用户坐在沙发上离屏幕较远，所以界面要文字大、对比强、信息层级清楚、焦点明显、操作路径短。按钮和卡片不能太小，边距和间距要充足，焦点态要能在远距离下看清。

**易错点：** 10-foot UI 不只是把手机 UI 放大，而是交互和布局都要围绕遥控器和远距离观看重新设计。

**关联知识点：** [10-foot UI](../知识点梳理/TV开发基础.md#10-foot-ui)

<a id="tv-应用为什么要重点关注焦点"></a>
###### TV 应用为什么要重点关注焦点

答案：

**简答：** 因为 TV 端用户靠遥控器操作，焦点就是当前操作目标。没有焦点或焦点不明确，用户就不知道按确认键会触发什么。

**展开回答：** TV 端不像手机可以直接触摸控件。用户需要通过方向键移动焦点，再通过确认键触发操作。因此每个页面都要有默认焦点、清晰焦点态和可预期的焦点移动路径。焦点丢失会导致遥控器无响应，焦点错乱会导致用户误操作。

**易错点：** 焦点态、选中态、点击态不是同一个概念，不能混用。

**关联知识点：** [焦点基础](../知识点梳理/焦点和遥控器.md#焦点基础)

<a id="leanback-和-compose-for-tv-怎么选"></a>
###### Leanback 和 Compose for TV 怎么选

答案：

**简答：** 老项目或传统 View 体系可以继续用 Leanback，新项目或 Compose 技术栈可以评估 Compose for TV，关键看团队经验、项目生命周期和交互复杂度。

**展开回答：** Leanback 提供 TV 常用页面结构和组件，适合传统 TV 视频类界面和老项目维护。Compose for TV 更适合新项目、声明式 UI 和已经使用 Compose 的团队。但无论哪种方案，都要自己处理好焦点、遥控器、列表和性能，不是换技术栈就自动解决 TV 体验问题。

**易错点：** 选型不能只看“新不新”，要看项目已有架构、团队熟悉度、设备性能和稳定性要求。

**关联知识点：** [Leanback 和 Compose for TV](../知识点梳理/TV开发基础.md#leanback-和-compose-for-tv)

<a id="tv-应用-manifest-和发布要注意什么"></a>
###### TV 应用 Manifest 和发布要注意什么

答案：

**简答：** 要保证 TV Launcher 能识别应用入口，声明正确设备能力，准备适合 TV 的图标和 banner，并按目标市场最新规则核对上架要求。

**展开回答：** TV 应用通常需要 TV 启动入口、banner、横屏配置，并避免强依赖触摸屏。发布前要检查遥控器是否能操作所有主要功能、默认焦点是否合理、返回路径是否清晰、播放和弱网是否稳定。Google Play 或厂商市场规则可能变化，最终要以最新官方规则为准。

**易错点：** 能安装不代表能被 TV 桌面正确展示，也不代表符合 TV 上架质量要求。

**关联知识点：** [Manifest 和启动入口](../知识点梳理/TV发布和调试.md#manifest-和启动入口)
