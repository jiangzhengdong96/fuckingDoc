<a id="android-tv-焦点机制怎么理解"></a>
###### Android TV 焦点机制怎么理解

答案：

**简答：** TV 焦点就是遥控器当前操作目标，方向键负责移动焦点，确认键负责触发当前焦点控件。

**展开回答：** 系统会根据当前焦点 View 和方向键做焦点搜索，寻找下一个可聚焦 View。开发时要保证页面有默认焦点、控件可聚焦、焦点态明显、焦点移动路径可预期。复杂布局可以通过 `nextFocus`、自定义焦点搜索、列表焦点恢复等方式控制。

**易错点：** 焦点不是业务选中态，不能只用 selected 替代 focus。

**关联知识点：** [焦点基础](../知识点梳理/焦点和遥控器.md#焦点基础)

<a id="页面首次进入如何下发默认焦点"></a>
###### 页面首次进入如何下发默认焦点

答案：

**简答：** 等目标 View 可见、可聚焦并完成布局后，再调用 `requestFocus()`。

**展开回答：** 页面首次进入时，View 可能还没 attach、列表数据还没提交、RecyclerView item 还没创建，如果立即请求焦点可能失败。常见做法是 `view.post { requestFocus() }`、列表数据提交完成后请求焦点、监听目标 item attach 后请求焦点。请求前要检查目标是否可见、可用、可聚焦。

**易错点：** 不要反复无条件下发默认焦点，否则用户刚移动焦点就会被抢回去。

**关联知识点：** [默认焦点下发](../知识点梳理/焦点和遥控器.md#默认焦点下发)

<a id="焦点丢失怎么排查"></a>
###### 焦点丢失怎么排查

答案：

**简答：** 先找“当前焦点去哪了”，再查 View 是否可聚焦、是否被刷新重建、是否被隐藏、是否有父容器或按键拦截。

**展开回答：** 可以打印 `decorView.findFocus()`，确认焦点是 null、落到错误 View、还是落到不可见区域。然后检查目标 View 的 `focusable`、`visibility`、`enabled`、attach 状态、父容器焦点策略、列表刷新、弹窗层级、按键消费。RecyclerView 场景重点看 item 是否被 `notifyDataSetChanged()` 重建、是否还没 attach 就请求焦点。

**易错点：** 不要只在丢失后直接 `requestFocus()` 兜底，要先定位为什么丢，否则后续还会反复出现。

**关联知识点：** [常见坑](../知识点梳理/焦点和遥控器.md#常见坑)

<a id="recyclerview-列表焦点为什么容易出问题"></a>
###### RecyclerView 列表焦点为什么容易出问题

答案：

**简答：** 因为 RecyclerView 会复用、刷新、滚动和 detach item，焦点 View 可能被重建或移出屏幕。

**展开回答：** TV 列表里 item 是焦点目标。数据刷新、全量 notify、图片加载改变尺寸、焦点放大触发布局、滚动到边缘、嵌套 RecyclerView 抢焦点，都可能导致焦点丢失或错乱。解决方向是稳定 item 尺寸、使用 DiffUtil、保存业务 id、等待 item attach 后恢复焦点、避免在 onBind 中无条件 requestFocus。

**易错点：** “列表焦点丢了就 requestFocus 第一个 item”只是兜底，不是完整方案。返回恢复和数据刷新要恢复用户之前的位置。

**关联知识点：** [列表焦点](../知识点梳理/焦点和遥控器.md#列表焦点)

<a id="tv-嵌套列表怎么做焦点恢复"></a>
###### TV 嵌套列表怎么做焦点恢复

答案：

**简答：** 保存外层栏目和内层 item 的稳定标识，返回时先恢复滚动位置，再等目标 item attach 后请求焦点。

**展开回答：** TV 首页常见外层竖向列表嵌套内层横向列表。焦点恢复要保存外层栏目 id、内层内容 id、外层 position、内层 position。返回后先提交数据，再滚动到目标行和目标列，等 ViewHolder attach 后调用 `requestFocus()`。如果目标内容不存在，就降级到同位置、邻近 item 或默认焦点。

**易错点：** 只保存 position 不够稳定，因为数据插入、删除、排序后 position 可能变化。

**关联知识点：** [横竖嵌套列表](../知识点梳理/TV列表和焦点性能.md#横竖嵌套列表)

<a id="遥控器按键事件怎么处理"></a>
###### 遥控器按键事件怎么处理

答案：

**简答：** 根据业务在合适层级处理 KeyEvent，方向键不要无条件消费，确认键要兼容 `DPAD_CENTER` 和 `ENTER`。

**展开回答：** Activity、ViewGroup、View 都可能处理按键。方向键通常交给系统焦点搜索，只有在需要特殊路径、播放器控制、弹窗限制时才拦截。返回 `true` 表示消费事件，返回 `false` 表示继续分发。长按和连续按键要看 `repeatCount`，避免重复触发业务。

**易错点：** 在 Activity 高层直接消费所有方向键，会导致页面焦点完全不动。

**关联知识点：** [遥控器按键](../知识点梳理/焦点和遥控器.md#遥控器按键)

<a id="弹窗关闭后焦点怎么恢复"></a>
###### 弹窗关闭后焦点怎么恢复

答案：

**简答：** 弹窗打开前保存当前焦点，关闭后如果原焦点仍可用就恢复，否则降级到页面默认焦点。

**展开回答：** 弹窗显示后焦点应进入弹窗内部，避免焦点跑到底层页面。关闭时检查打开前的 View 是否还 attach、可见、可聚焦，如果可用就 `requestFocus()`；如果页面刷新或原 View 不存在，就恢复到默认按钮、当前列表 item 或第一个可操作控件。

**易错点：** 弹窗关闭后不恢复焦点，用户会感觉遥控器突然失效。

**关联知识点：** [弹窗和浮层焦点](../知识点梳理/焦点和遥控器.md#弹窗和浮层焦点)
