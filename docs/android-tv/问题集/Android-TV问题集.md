<a id="页面首次进入焦点怎么下发"></a>
###### 页面首次进入焦点怎么下发

问题：

- 页面打开后没有默认焦点。
- 用户按确认键没有反应。
- 用户必须先按方向键几次，焦点才出现。

可能原因：

- 页面没有主动设置默认焦点。
- 目标 View 还没布局完成就调用了 `requestFocus()`。
- RecyclerView 数据还没加载完成，目标 item 还不存在。
- loading、空态、弹窗或父容器抢走了焦点。
- 目标 View 不可见、不可用或没有 `focusable=true`。

排查步骤：

- 打印页面进入后 `decorView.findFocus()`，确认当前焦点是谁。
- 检查默认目标 View 是否可见、可用、可聚焦、已 attach。
- 如果目标在 RecyclerView 中，确认 adapter 是否已有数据，目标 ViewHolder 是否已经创建。
- 检查是否有 loading、弹窗、遮罩层在页面上方。
- 检查是否在 `onCreate()` 或 `onViewCreated()` 太早调用了 `requestFocus()`。

处理方案：

- 普通 View 可以在布局完成后下发焦点：

```java
targetView.post(() -> targetView.requestFocus());
```

- RecyclerView item 要等数据提交和 item attach 后再请求焦点。
- 默认焦点要有降级策略：目标 item 不存在时，聚焦第一个可操作入口。
- 请求焦点前统一判断：

```java
private boolean canRequestFocus(View view) {
    return view != null
            && view.isShown()
            && view.isEnabled()
            && view.isFocusable();
}
```

- 不要在每次页面刷新时都强制下发默认焦点，只在首次进入或明确需要兜底时处理。

<a id="焦点丢失怎么排查"></a>
###### 焦点丢失怎么排查

问题：

- 按方向键或确认键没有反应。
- 页面看不到焦点态。
- 焦点落到不可见区域或错误控件。

可能原因：

- 当前焦点 View 被隐藏、禁用、移除或 detach。
- 列表刷新导致持有焦点的 item 被重建。
- 弹窗、loading、遮罩层抢走焦点。
- 父容器拦截并消费了方向键。
- 目标 View 没有设置可聚焦。
- 焦点态 UI 没有正确显示，让用户以为焦点丢了。

排查步骤：

- 打印当前焦点：

```java
View focused = getWindow().getDecorView().findFocus();
Log.d("TvFocus", "focused=" + focused);
```

- 在 `dispatchKeyEvent()` 打印按键和消费结果。
- 给关键 View 加 `OnFocusChangeListener`，记录焦点进入和离开。
- 检查丢失前是否发生了 `notifyDataSetChanged()`、页面刷新、弹窗显示、loading 切换。
- 用 Layout Inspector 或日志确认当前焦点 View 是否仍在窗口里。

处理方案：

- 如果是刷新导致丢失，改用 DiffUtil、稳定 id、局部刷新。
- 如果是 item detach，保存业务 id，等 item 重新 attach 后恢复焦点。
- 如果是遮罩层抢焦点，明确遮罩层是否需要可聚焦，不需要就取消。
- 如果是按键被消费，调整拦截层级，只消费业务需要的按键。
- 增加焦点兜底：当 `findFocus()` 为 null 时，把焦点恢复到页面默认入口。

<a id="列表刷新后焦点丢失怎么办"></a>
###### 列表刷新后焦点丢失怎么办

问题：

- 列表接口刷新后，焦点消失。
- 焦点回到第一个 item，而不是用户当前 item。
- 当前 item 明明还存在，但焦点恢复失败。

可能原因：

- 使用 `notifyDataSetChanged()` 全量刷新。
- item 没有稳定业务 id。
- 数据提交后立即请求焦点，目标 ViewHolder 还没创建。
- DiffUtil 判断不准确，导致 item 被当成新对象重建。
- item 图片加载或布局变化导致焦点位置变化。

排查步骤：

- 确认刷新方式，是全量 notify 还是 DiffUtil。
- 打印刷新前当前焦点 item 的业务 id 和 position。
- 打印刷新后该业务 id 是否还存在。
- 监听目标 item attach，确认请求焦点时机。
- 检查 item 尺寸是否因数据变化而变化。

处理方案：

- 优先使用 DiffUtil 或 ListAdapter。
- 保存业务 id，而不是只保存 position。
- 数据刷新后按业务 id 找目标 position。
- 先滚动到目标 position，再等 item attach 后请求焦点。
- 目标不存在时降级到邻近 item 或默认焦点。

<a id="返回页面后焦点怎么恢复"></a>
###### 返回页面后焦点怎么恢复

问题：

- 从详情页返回首页后，焦点不在刚才点击的卡片上。
- 返回后列表位置正确，但焦点没有出现。
- 返回后焦点跑到导航栏或第一个 item。

可能原因：

- 进入详情前没有保存焦点位置。
- 只保存 position，数据变化后 position 已经不对应原内容。
- 返回后列表还没恢复滚动位置就 requestFocus。
- 目标 item 未 attach。
- 页面重新创建后状态没有恢复。

排查步骤：

- 进入详情前保存外层栏目 id、内层内容 id、position。
- 返回后确认数据是否已恢复。
- 确认目标 item 是否在当前 adapter 中。
- 确认 `scrollToPosition()` 和 `requestFocus()` 的顺序。

处理方案：

- 保存稳定业务 id + position 作为辅助。
- 返回后先恢复数据，再恢复滚动，再恢复焦点。
- RecyclerView 使用 attach 回调或 `post` 等待布局完成。
- 如果目标内容不存在，降级到同栏目第一个或页面默认焦点。

<a id="焦点移动方向不符合预期怎么办"></a>
###### 焦点移动方向不符合预期怎么办

问题：

- 按右键没有到右边按钮。
- 按下键跳到很远的控件。
- 网格列表中焦点斜着跳。

可能原因：

- 默认焦点搜索按几何位置找最近候选，不符合业务路径。
- 控件边界、放大效果、margin、translation 影响候选判断。
- 某些不可见或透明控件仍然可聚焦。
- 多个候选 View 距离接近，系统选择结果不稳定。
- 嵌套列表父子同时参与焦点搜索。

排查步骤：

- 打印当前焦点和按键方向。
- 标记所有可聚焦 View，确认候选范围。
- 检查是否有隐藏但可聚焦的 View。
- 检查 `nextFocusLeft/Right/Up/Down` 是否配置错误。

处理方案：

- 稳定布局可用 `nextFocus` 指定方向。
- 动态列表不要硬写不稳定 id，改用自定义焦点策略或焦点恢复逻辑。
- 移除不该参与焦点的 View 的 `focusable`。
- 对复杂容器重写焦点搜索，按业务规则返回目标。

<a id="遥控器按键无响应怎么办"></a>
###### 遥控器按键无响应怎么办

问题：

- 按方向键不动。
- 按确认键不点击。
- 某些设备确认键无效。
- 长按触发多次或不触发。

可能原因：

- 当前没有焦点。
- 高层 `dispatchKeyEvent()` 消费了事件。
- 只处理了 `DPAD_CENTER`，漏了 `ENTER`。
- 只处理 `ACTION_DOWN` 或 `ACTION_UP` 的逻辑不一致。
- 长按 repeat 事件被重复处理。
- 焦点 View 没有 click listener 或不可用。

排查步骤：

- 在 Activity `dispatchKeyEvent()` 打印 keyCode、action、repeatCount。
- 打印当前焦点 View。
- 检查返回值，确认事件在哪里被消费。
- 对比 ADB keyevent 和真实遥控器 keyCode。

处理方案：

- 方向键默认不要高层消费，让系统焦点搜索处理。
- 确认键同时兼容 `KEYCODE_DPAD_CENTER` 和 `KEYCODE_ENTER`。
- 对业务动作统一选择 `ACTION_UP` 或 `ACTION_DOWN`，避免执行两次。
- 长按按键根据 `repeatCount` 做节流或特殊处理。
- 没有焦点时先恢复默认焦点。

<a id="弹窗关闭后焦点丢失怎么办"></a>
###### 弹窗关闭后焦点丢失怎么办

问题：

- 弹窗关闭后页面按键无响应。
- 焦点回不到打开弹窗前的按钮。
- 焦点跑到底层不可见控件。

可能原因：

- 打开弹窗前没有保存当前焦点。
- 弹窗关闭时原 View 已被刷新或销毁。
- 弹窗自身没有正确释放焦点。
- 底层页面正在刷新或显示 loading。

排查步骤：

- 弹窗打开前记录 `findFocus()`。
- 弹窗关闭时检查原 View 是否 attach、可见、可聚焦。
- 检查弹窗关闭同时是否触发页面刷新。
- 打印关闭后当前焦点。

处理方案：

- 打开弹窗前保存焦点 View 或业务 id。
- 关闭后优先恢复原焦点。
- 原焦点不可用时降级到默认按钮或当前列表 item。
- 弹窗内焦点要限制在弹窗内，避免跑到底层。

<a id="播放页控制层焦点混乱怎么办"></a>
###### 播放页控制层焦点混乱怎么办

问题：

- 控制层隐藏后，焦点还在不可见按钮上。
- 按确认键不知道触发了什么。
- 清晰度面板关闭后焦点丢失。
- 返回键行为不稳定。

可能原因：

- 控制层显示/隐藏时没有转移焦点。
- 控制层按钮隐藏后仍可聚焦。
- 多个浮层同时可聚焦。
- 返回键优先级没有定义清楚。

排查步骤：

- 列出播放页所有层级：错误页、弹窗、控制层、视频根容器。
- 打印每次显示/隐藏后的当前焦点。
- 检查隐藏层里的 View 是否仍然 `focusable=true`。
- 检查返回键处理顺序。

处理方案：

- 明确焦点优先级：错误页 > 面板 > 控制层 > 视频根容器。
- 控制层显示时恢复上次控制按钮焦点或默认到播放暂停按钮。
- 控制层隐藏时把焦点交给视频根容器，或记录焦点等待下次显示恢复。
- 面板关闭后恢复到打开入口按钮。
- 返回键先关闭最上层浮层，再退出页面。

<a id="recyclerview-焦点放大后抖动怎么办"></a>
###### RecyclerView 焦点放大后抖动怎么办

问题：

- item 获得焦点后列表抖动。
- 放大后遮挡或挤动旁边 item。
- 快速移动焦点时画面闪动。

可能原因：

- 焦点放大改变了布局测量尺寸。
- item 间距不足，放大后和周围元素冲突。
- 父容器裁剪阴影或放大区域。
- 焦点动画过长或重复创建。

排查步骤：

- 检查焦点态是否修改了 `layoutParams`、margin、padding。
- 检查是否使用 scale 但父容器 `clipChildren=true` 导致裁剪。
- 检查 item 固定尺寸和间距。
- 连续按键观察动画是否堆积。

处理方案：

- 外层 item 固定尺寸，内部内容用 `scaleX/scaleY` 做视觉放大。
- 给列表设置合适 padding 和 item 间距。
- 必要时设置父容器不裁剪子 View。
- 缩短焦点动画，复用动画或状态选择器，避免复杂实时计算。

<a id="tv-列表快速按键卡顿怎么办"></a>
###### TV 列表快速按键卡顿怎么办

问题：

- 连续按遥控器方向键时列表掉帧。
- 图片加载慢，焦点移动卡顿。
- 首页嵌套列表滑动不流畅。

可能原因：

- item 布局层级太深。
- 图片过大或解码压力大。
- 全量刷新频繁。
- 焦点动画复杂。
- 主线程做数据处理、排序、过滤。
- 嵌套 RecyclerView 创建和回收成本高。

排查步骤：

- 用 Profiler 查看 CPU、内存、GC。
- 打印列表刷新频率和 notify 类型。
- 检查图片实际加载尺寸。
- 检查焦点动画是否触发布局。
- 在低端真机上连续按键压测。

处理方案：

- 使用 DiffUtil 和局部刷新。
- 简化 item 布局，固定尺寸。
- 图片按显示尺寸加载，使用占位图和缓存。
- 数据转换放后台线程。
- 嵌套列表共享 RecycledViewPool，合理设置缓存。
- 控制预加载数量，避免一次性加载过多内容。
