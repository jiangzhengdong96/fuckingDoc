### Java 反射知识点清单

###### 内容概述

本文件记录 Java 反射相关知识点，包括反射基础和 Class 对象、动态加载和类初始化、获取类信息、构造方法和对象创建、字段和方法调用、注解和泛型反射、动态代理和框架能力、Android 使用限制和性能安全，以及关联面试题。

###### 使用场景

- 框架初始化、对象创建、字段注入、方法调用、注解扫描和动态代理中经常会用到反射。
- Android 中路由、序列化、依赖注入、ViewBinding/DataBinding、插件化、兼容处理和部分三方库适配可能会用到反射。
- 反射会绕开一部分编译期检查，带来性能、混淆、隐藏 API、访问边界和可维护性问题，业务代码中应优先使用普通调用或明确的接口抽象。

<a id="反射基础和-class-对象"></a>
###### 反射基础和 Class 对象

- 反射是指程序在运行期通过 `Class`、`Constructor`、`Field`、`Method` 等反射 API 获取类信息、创建对象、访问字段和调用方法的能力。它的核心不是“写代码时直接调用”，而是“运行时再根据类信息决定做什么”。
- JVM 加载一个类后，会为这个类型创建对应的 `Class` 对象。`Class` 对象保存了类名、包名、父类、接口、构造方法、字段、方法、注解等元信息。拿到 `Class` 对象，就相当于拿到了运行期描述这个类型的入口。
- `Class` 不只表示普通类，也可以表示接口、枚举、注解、数组、基本类型和 `void`。例如 `String.class`、`int.class`、`void.class`、`String[].class` 都是 `Class` 对象。
- `Class` 对象不是由业务代码直接 `new` 出来的，`Class` 没有公开构造方法。它由 JVM 在类加载或定义类时创建和维护。
- 同一个类型通常对应一个 `Class` 对象，但这个“同一个”要带上类加载器维度。同名类如果由不同 `ClassLoader` 加载，可能得到不同的 `Class` 对象，类型判断和强转也会受到影响。
- 反射适合解决框架层的通用问题，例如不知道具体类型时创建对象、根据注解绑定字段、扫描方法、调用插件入口、生成代理对象等。普通业务逻辑如果已经知道类型，直接调用通常更清晰、更安全。

<a id="动态加载和类初始化"></a>
###### 动态加载和类初始化

- Java 类不是程序启动时一次性全部加载，通常是在首次主动使用时由 JVM 按需加载、验证、准备、解析和初始化。反射常见于“运行时才知道要加载哪个类”的场景，所以经常和动态加载一起出现。
- `Class.forName("完整类名")` 常用于通过字符串动态加载类。它的常用重载 `Class.forName(String)` 默认会触发类初始化，也就是可能执行静态代码块和静态字段初始化。
- 如果只想加载类但暂时不初始化，可以使用 `Class.forName(name, false, classLoader)`；如果使用 `ClassLoader.loadClass(name)`，通常也只是加载类，不会立刻初始化。
- `类名.class` 是编译期明确引用，类型是否存在能被编译器检查；`Class.forName()` 更灵活，但类名写错、类加载器不对、依赖缺失等问题会推迟到运行期暴露。
- 插件化、热修复、SPI、JDBC 老写法、部分路由框架都可能涉及动态加载。Android 中还要注意不同 DexClassLoader / PathClassLoader 带来的类隔离和类型不相等问题。
- 不要把文档示意里的 `new Class(...)` 当成真实代码。`Class` 的构造过程由 JVM 管理，业务代码不能直接创建 `Class` 实例。

<a id="获取类信息"></a>
###### 获取类信息

- 获取 `Class` 对象常见有三种方式：

| 方式 | 示例 | 特点 |
|---|---|---|
| 类字面量 | `String.class` | 编译期已知类型，简单直接，不会因为字符串类名写错导致运行时找不到类 |
| 对象实例 | `"hello".getClass()` | 已经有对象实例时使用，拿到的是实际运行时类型 |
| 完整类名 | `Class.forName("java.lang.String")` | 运行时通过字符串加载类，常见于配置化、插件化、JDBC 老写法 |

- `类名.class` 适合编译期明确的类型；`obj.getClass()` 适合根据对象拿真实类型；`Class.forName()` 适合通过类全名动态加载，但类名写错会抛出 `ClassNotFoundException`，并且默认会触发类初始化。
- 常用类信息 API：

| API | 作用 |
|---|---|
| `getName()` | 获取完整类名 |
| `getSimpleName()` | 获取简单类名 |
| `getPackage()` | 获取包信息 |
| `getSuperclass()` | 获取父类 |
| `getInterfaces()` | 获取实现的接口 |
| `isInterface()` / `isEnum()` / `isAnnotation()` / `isArray()` | 判断类型特征 |
| `getModifiers()` | 获取修饰符，配合 `Modifier` 判断 public、private、static 等 |

- `getXxx()` 和 `getDeclaredXxx()` 是反射里很重要的一组区别：`getMethods()`、`getFields()`、`getConstructors()` 只关注 public 成员，并且会包含继承来的 public 成员；`getDeclaredMethods()`、`getDeclaredFields()`、`getDeclaredConstructors()` 获取当前类声明的成员，包含 private、protected、默认访问级别和 public，但不包含父类声明的成员。
- 如果需要递归扫描父类字段或方法，不能只调用一次 `getDeclaredFields()`，而是要沿着 `getSuperclass()` 一层层向上处理。

<a id="构造方法和对象创建"></a>
###### 构造方法和对象创建

- 反射创建对象通常通过 `Constructor` 完成：

```java
Class<User> clazz = User.class;
Constructor<User> constructor = clazz.getDeclaredConstructor(String.class, int.class);
User user = constructor.newInstance("Tom", 18);
```

- `getConstructor(...)` 只能获取 public 构造方法；`getDeclaredConstructor(...)` 可以获取当前类声明的构造方法，包括 private 构造方法。如果要调用非 public 构造方法，通常还需要在允许的情况下调用 `setAccessible(true)`。
- 旧笔记里提到的 `Class.newInstance()` 只能调用 public 无参构造方法，并且异常处理不够清晰。这个方法从 Java 9 开始已经被标记为 deprecated，推荐改用 `clazz.getDeclaredConstructor().newInstance()`。
- 通过反射创建对象时常见异常：

| 异常 | 常见原因 |
|---|---|
| `ClassNotFoundException` | `Class.forName()` 的类名不存在或类加载器找不到 |
| `NoSuchMethodException` | 构造方法参数类型不匹配，或没有对应构造方法 |
| `InstantiationException` | 类型不能实例化，例如抽象类、接口 |
| `IllegalAccessException` | 访问权限不足 |
| `InvocationTargetException` | 构造方法内部抛出异常，被反射包装起来 |

<a id="字段和方法调用"></a>
###### 字段和方法调用

- 访问字段通常通过 `Field` 完成：

```java
Field field = User.class.getDeclaredField("name");
field.setAccessible(true);
Object value = field.get(user);
field.set(user, "Jerry");
```

- 调用方法通常通过 `Method` 完成：

```java
Method method = User.class.getDeclaredMethod("setName", String.class);
method.setAccessible(true);
method.invoke(user, "Jerry");
```

- 反射调用实例方法时，`invoke()` 第一个参数是目标对象；调用静态方法时，第一个参数可以传 `null`。参数类型必须和方法签名匹配，基本类型和包装类型、可变参数、重载方法都要特别注意。
- `setAccessible(true)` 的含义不是“这个成员一定可以访问”，而是请求关闭 Java 语言访问检查。现代 Java 的模块系统、Android 的隐藏 API 策略、安全策略都可能让访问失败。Java 9 以后还可以使用 `trySetAccessible()` 判断是否能成功打开访问。
- 反射访问 `final` 字段、静态字段、私有字段要谨慎。即使能通过反射读取，也不代表所有场景都能安全写入；对 `static final` 常量、record 字段、隐藏类字段等，现代 JDK 对可修改性有更多限制。
- 常见字段和方法 API：

| API | 作用 |
|---|---|
| `getField()` / `getFields()` | 获取 public 字段 |
| `getDeclaredField()` / `getDeclaredFields()` | 获取当前类声明字段 |
| `Field.get()` / `Field.set()` | 读取或设置字段值 |
| `getMethod()` / `getMethods()` | 获取 public 方法 |
| `getDeclaredMethod()` / `getDeclaredMethods()` | 获取当前类声明方法 |
| `Method.invoke()` | 反射调用方法 |

<a id="注解和泛型反射"></a>
###### 注解和泛型反射

- 注解本身也是一种类型，所有注解都继承自 `java.lang.annotation.Annotation`。运行期读取注解需要反射 API，并且注解必须使用 `@Retention(RetentionPolicy.RUNTIME)`，否则运行期读不到。
- 常见注解读取方式：

```java
Route route = clazz.getAnnotation(Route.class);
boolean hasRoute = clazz.isAnnotationPresent(Route.class);
Annotation[] annotations = method.getDeclaredAnnotations();
```

- 读取字段、方法、构造方法上的注解和读取类注解类似；读取方法参数注解时通常会得到二维数组，因为一个方法有多个参数，每个参数又可能有多个注解。
- 注解 + 反射是很多运行时框架的基础，例如根据注解找路由表、接口方法、字段映射、序列化字段名等。但 Android 中大量运行时反射扫描可能影响启动性能，所以更常见的优化是编译期注解处理器、KSP、APT 或生成代码。
- Java 泛型主要通过类型擦除实现，运行期不能直接拿到普通对象的完整泛型实参，例如不能直接判断 `obj instanceof List<String>`。但部分反射 API 可以读取声明处保留的泛型信息，例如字段、方法返回值、父类泛型参数：

```java
Field field = Repository.class.getDeclaredField("items");
Type type = field.getGenericType();
```

- 常见泛型反射类型包括 `Type`、`ParameterizedType`、`TypeVariable`、`WildcardType`、`GenericArrayType`。如果只用 `Class<?>`，通常只能表示原始类型；如果要解析 `List<User>` 里的 `User`，需要处理 `ParameterizedType`。
- 泛型数组不能直接 `new T[]`，但可以通过 `Array.newInstance(componentType, size)` 创建，再做受控强转：

```java
@SuppressWarnings("unchecked")
T[] array = (T[]) Array.newInstance(componentType, size);
```

<a id="动态代理和框架能力"></a>
###### 动态代理和框架能力

- JDK 动态代理通过 `Proxy.newProxyInstance()` 在运行期创建代理对象，并把方法调用转发给 `InvocationHandler`：

```java
UserApi api = (UserApi) Proxy.newProxyInstance(
        UserApi.class.getClassLoader(),
        new Class<?>[] { UserApi.class },
        (proxy, method, args) -> {
            System.out.println(method.getName());
            return null;
        }
);
```

- JDK 动态代理的核心限制是只能代理接口，不能直接代理普通类。需要代理类时，常见方案是字节码生成、ASM、Byte Buddy、CGLIB，Android 上也要考虑运行时字节码生成限制和兼容性。
- Retrofit 这类框架常见做法是定义接口，运行期通过动态代理拦截接口方法调用，再根据方法注解、参数注解和返回类型构建请求。
- 反射和动态代理经常一起出现：反射负责读取接口方法、注解、泛型返回类型等元信息；动态代理负责拦截方法调用，把“调用接口方法”转换成框架内部逻辑。

<a id="android-使用限制和性能安全"></a>
###### Android 使用限制和性能安全

- Android 中反射常见于框架、工具库和兼容层，但业务代码要谨慎使用。原因包括：反射比直接调用慢、可读性差、容易受混淆影响、隐藏 API 访问可能失败、系统版本差异大。
- 混淆会影响反射。通过字符串访问类名、字段名、方法名时，如果 R8/ProGuard 改名了，运行期可能找不到目标。需要根据场景添加 `-keep` 规则，或改用注解生成代码、接口抽象等更稳定方案。
- Android 9（API 28）以后对非 SDK 接口有隐藏 API 限制，反射访问系统隐藏字段或方法可能失败，并且不同系统版本和厂商 ROM 行为可能不同。不要把反射系统隐藏 API 当成稳定能力。
- 反射可能影响启动性能。常见优化方式：减少启动阶段全量扫描、缓存 `Class` / `Field` / `Method` / `Constructor`、避免频繁 `setAccessible(true)`、把运行时扫描改成编译期生成索引。
- 反射绕开了一部分编译期检查。方法名、字段名、参数类型写错时，问题会从编译期推迟到运行期；`Method.invoke()` 内部抛出的真实异常会被 `InvocationTargetException` 包装，需要通过 `getCause()` 查看原始原因。
- 安全和封装角度看，反射可以访问非 public 成员，但这不代表应该随意访问。框架可以在边界清晰的地方使用反射；业务代码频繁访问私有成员通常意味着设计需要调整。
