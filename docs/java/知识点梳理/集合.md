### Java 集合知识点清单

###### 内容概述

本文件记录 Java 集合相关知识点，包括集合体系、底层数据结构、List、Set、Map、Queue、Iterator、Collections 工具类、排序和比较、Android 常见集合、选择建议、常见坑和关联面试题。

###### 使用场景

- `List` 常用于 RecyclerView、ViewPager、Adapter 数据源和接口列表数据。
- `Map` 常用于缓存、参数组装、索引映射和对象去重辅助。
- `Set` 常用于去重、状态集合和权限/标签集合。
- `Queue` 常用于任务队列、消息排队和简单生产消费场景。

###### 集合体系

- `Collection` 是单列集合的顶层接口，常见子接口有 `List`、`Set`、`Queue`。
- `Map` 是双列集合接口，保存 key-value 映射关系，不继承 `Collection`。
- `List`、`Set`、`Queue` 都属于 `Collection` 体系。
- `Map` 是独立体系，常见实现类有 `HashMap`、`LinkedHashMap`、`TreeMap`、`Hashtable`、`ConcurrentHashMap`。
- `List` 常见实现类有 `ArrayList`、`LinkedList`、`Vector`。
- `Set` 常见实现类有 `HashSet`、`LinkedHashSet`、`TreeSet`。
- `Queue` 常见实现类有 `ArrayDeque`、`LinkedList`、`PriorityQueue`。
- `Iterator` 是统一遍历模型，调用方不用关心集合内部结构。
- `Collections` 是集合工具类，提供排序、洗牌、不可变包装、同步包装、空集合、单元素集合等工具方法。

###### 底层数据结构

- 数组：内存连续，按下标查询快，插入删除可能需要移动元素。
- 链表：节点通过引用连接，按下标查询慢，在已知节点附近插入删除更灵活。
- 哈希表：通过 key 的 hash 值定位桶位，适合快速查找、插入和删除。
- 哈希冲突：不同 key 可能定位到同一个桶，需要链表、红黑树等结构继续存储。
- 二叉树：每个节点最多两个子节点，常用于理解树形查找和遍历。
- 满二叉树：如果层数为 `k`，节点数是 `2^k - 1`。
- 二叉树节点通常包含数据、左子节点、右子节点。
- 先序遍历：根、左、右。
- 中序遍历：左、根、右。
- 后序遍历：左、右、根。
- 红黑树是一种自平衡二叉查找树，`TreeMap`、`TreeSet` 常见底层实现与红黑树相关。
- `HashMap` 在 JDK 8 以后常见结构是数组 + 链表 + 红黑树。
- `ArrayXxx` 常见底层是数组，查询快，增删相对慢。
- `LinkedXxx` 常见底层是链表，查询慢，增删更灵活。
- `HashXxx` 常见底层是哈希表，依赖 `hashCode()` 和 `equals()`。
- `TreeXxx` 常见底层是红黑树，依赖自然排序或比较器排序。

###### List

- `List` 有序、可重复，支持按索引访问。
- `List` 判断元素是否相等通常依赖 `equals()`，不是 `==`。
- `contains()`、`indexOf()` 等方法会使用 `equals()` 判断元素相等。
- 如果自定义对象需要在 `List` 中查找，通常要正确重写 `equals()`。
- 如果不在 `List` 中查找元素，不重写 `equals()` 也不一定影响基本存储。
- `ArrayList` 底层是数组，随机访问快，尾部追加常用。
- `ArrayList` 中间插入、删除可能需要移动元素。
- `ArrayList` 线程不安全，日常单线程集合场景默认优先使用。
- `ArrayList` 常见初始无参构造会先使用空数组，第一次添加元素时扩容到默认容量。
- `ArrayList` 常见扩容方式约为原容量的 1.5 倍，扩容需要创建新数组并复制旧元素。
- 已知数据量较大时，可以预估容量或使用 `ensureCapacity()` 减少扩容次数。
- `Arrays.asList()` 返回的是固定长度 List，不能 `add()` / `remove()`。
- `Arrays.asList()` 返回的 List 和原数组关联，修改数组元素或 `set()` 元素可能互相影响。
- `Arrays.asList(new int[]{1, 2, 3})` 得到的是一个元素类型为 `int[]` 的 List，不是三个 `Integer` 元素。
- `subList()` 返回的是原 List 的视图，不是独立新集合。
- 修改 `subList()` 会影响原 List；原 List 结构性修改后继续使用旧 `subList()` 可能抛异常。
- `LinkedList` 底层是双向链表，按下标查询慢。
- `LinkedList` 在已知节点附近插入删除更灵活，但日常业务不一定比 `ArrayList` 更快。
- `LinkedList` 也实现了 `Deque`，可以当队列或双端队列使用。
- `Vector` 底层也是数组，方法带同步，线程安全但效率较低，属于较老的集合类。
- 如果没有明确线程安全和历史兼容要求，通常不用 `Vector`。
- `Vector` 可以配置 `capacityIncrement`，`ArrayList` 没有这个增长因子参数，但也会自动扩容。
- Android 开发中，列表数据源通常优先使用 `ArrayList`。

###### Set

- `Set` 元素不可重复。
- `Set` 不支持按下标获取元素，通常使用迭代器或增强 for 遍历。
- `Set` 遇到重复元素时通常是添加失败，不是覆盖旧元素。
- `HashSet` 底层通常基于 `HashMap`，元素作为 key 保存。
- `HashSet` 不保证遍历顺序，不能依赖输出顺序。
- `HashSet` 判断唯一性依赖 `hashCode()` 和 `equals()`。
- `LinkedHashSet` 基于哈希表和链表，既保证唯一性，又保留插入顺序。
- `LinkedHashSet` 的“有序”指按插入顺序迭代，不等于队列语义上的主动出队。
- `TreeSet` 底层常见是红黑树，元素唯一且有序。
- `TreeSet` 的有序来自自然排序或自定义 `Comparator`。
- `TreeSet` 判断元素是否重复，核心看比较结果是否为 `0`。
- `HashSet`、`LinkedHashSet`、`TreeSet` 都不是线程安全的。
- 需要线程安全 Set 时，可以考虑 `Collections.synchronizedSet()` 或并发集合方案。
- `HashSet` 和 `LinkedHashSet` 可以保存 `null`。
- `TreeSet` 使用自然排序时通常不允许放入 `null`；如果自定义比较器能处理 `null`，行为取决于比较器实现。
- 用 Set 去重时，自定义对象要正确重写 `equals()` 和 `hashCode()`。

###### Map

- `Map` 适合存储 key-value 数据。
- `Map` 的 key 唯一，value 可以重复。
- 相同 key 再次 `put()` 时会替换旧 value。
- `HashMap` 不是线程安全的，效率较高，日常单线程场景常用。
- `HashMap` 允许一个 `null` key，允许多个 `null` value。
- `HashMap` 默认负载因子常见是 `0.75`，用于在空间占用和查询效率之间折中。
- `HashMap` 容量通常保持为 2 的幂，方便通过位运算定位桶位。
- `HashMap` 扩容会重新分布桶位，成本较高，已知数据量时可以预估初始容量。
- JDK 8 常见树化条件是桶内链表节点数量达到阈值且数组容量足够大，否则可能优先扩容。
- JDK 8 常见说法：链表节点达到 `8` 且容量至少 `64` 时可能树化，节点减少到一定程度后可能退化为链表。
- `Hashtable` 是较老的同步 Map，方法大多使用 `synchronized`。
- `Hashtable` 不允许 `null` key 和 `null` value。
- `Hashtable` 继承自 `Dictionary`，`HashMap` 继承自 `AbstractMap`。
- 没有历史兼容要求时，通常优先用 `HashMap`，并发场景考虑 `ConcurrentHashMap`。
- `ConcurrentHashMap` 支持并发访问，但复合业务操作不一定天然原子。
- `ConcurrentHashMap` 不允许 `null` key 和 `null` value，避免并发场景下无法区分“没有值”和“值为 null”。
- `LinkedHashMap` 保留插入顺序，也可以用于实现简单 LRU 缓存。
- `LinkedHashMap` 可以按插入顺序迭代，也可以通过访问顺序模式实现 LRU 思路。
- `TreeMap` 按 key 排序，适合需要按自然顺序或自定义顺序遍历 key 的场景。
- `TreeMap` 的 key 必须可比较：要么 key 实现 `Comparable`，要么创建 `TreeMap` 时传入 `Comparator`。
- `TreeMap` 对 value 没有排序要求。
- `Properties` 是特殊的键值配置类，常用于读取 `.properties` 配置。
- `Properties` 常用方法：`load()` 读取配置，`getProperty()` 获取值，`setProperty()` 设置值。
- `WeakHashMap` 的 key 是弱引用，key 没有强引用时可能被 GC 回收，适合某些缓存场景。
- `IdentityHashMap` 使用 `==` 比较 key，不按 `equals()` 判断，属于特殊用途 Map。
- `EnumMap` 的 key 必须是枚举类型，适合枚举到值的高效映射。

HashMap 关键点：

- `HashMap` 不是简单“一个大数组直接存所有 value”，而是通过数组桶位保存节点，节点里包含 key、value、hash 和 next 等信息。
- `HashMap` 会先根据 key 计算 hash，再定位桶位。
- 如果桶位已有元素，会继续用 `equals()` 判断 key 是否相等。
- hash 不同，通常可以直接认为不是同一个 key。
- hash 相同，只能说明可能相等，还必须继续用 `equals()` 判断。
- 相等对象必须有相同的 `hashCode()`。
- `hashCode()` 相同的对象不一定相等，因为哈希冲突是允许存在的。
- 自定义对象作为 `HashMap` key 时，必须正确重写 `equals()` 和 `hashCode()`。
- 如果只重写 `equals()` 不重写 `hashCode()`，逻辑相等的对象可能落到不同桶，导致查询失败。
- `equals()` 用到的字段，通常也应该参与 `hashCode()` 计算。
- `equals()` 没用到的字段，不应该放进 `hashCode()` 计算。
- 多字段 hash 可以使用 `Objects.hash(firstName, lastName, age)`。
- 对引用类型比较时可以使用 `Objects.equals(a, b)`，避免空指针。

###### Queue

- `Queue` 表示队列，常见语义是先进先出。
- `offer()` 添加元素，失败时通常返回 `false`。
- `poll()` 取出并删除队头元素，队列为空时返回 `null`。
- `peek()` 查看队头元素但不删除，队列为空时返回 `null`。
- `Deque` 是双端队列，可以从队头和队尾插入、删除。
- `ArrayDeque` 是常用双端队列实现，通常比 `LinkedList` 更适合作为栈或队列。
- `PriorityQueue` 是优先级队列，不保证 FIFO，而是按自然排序或比较器决定出队顺序。
- `LinkedList` 同时实现了 `List` 和 `Deque`，但日常队列场景可优先考虑 `ArrayDeque`。

###### Iterator

- `Iterator` 是一种统一的数据访问模型。
- 使用 `Iterator` 的好处是对不同集合采用同一种遍历方式。
- 调用方不需要知道集合底层是数组、链表、哈希表还是树。
- 集合类返回的 `Iterator` 对象知道如何遍历当前集合。
- 遍历集合时如果需要删除当前元素，应优先使用 `Iterator.remove()`。
- 增强 for 底层通常也是迭代器模型。
- 遍历过程中直接调用集合自身的 `remove()`，可能触发 `ConcurrentModificationException`。

###### Collections 工具类

- `Collections.emptyList()` 创建不可变空 List。
- `Collections.emptySet()` 创建不可变空 Set。
- `Collections.emptyMap()` 创建不可变空 Map。
- `Collections.singletonList(value)` 创建不可变单元素 List。
- `Collections.singleton(value)` 创建不可变单元素 Set。
- `Collections.singletonMap(key, value)` 创建不可变单元素 Map。
- `Collections.unmodifiableList(list)` 把已有 List 包装成不可变视图。
- `Collections.unmodifiableSet(set)` 把已有 Set 包装成不可变视图。
- `Collections.unmodifiableMap(map)` 把已有 Map 包装成不可变视图。
- `Collections.synchronizedList(list)` 可以获得同步包装 List。
- `Collections.synchronizedSet(set)` 可以获得同步包装 Set。
- `Collections.synchronizedMap(map)` 可以获得同步包装 Map。
- `Collections.sort(list)` 可以对 List 排序。
- `Collections.shuffle(list)` 可以打乱 List 顺序。
- `List.of()`、`Set.of()`、`Map.of()` 是 Java 9+ 的不可变集合工厂方法，使用时要注意项目 Java 版本和 Android 兼容情况。
- `List.of()`、`Set.of()`、`Map.of()` 创建的集合不可变，且不允许 `null` 元素或 key/value。
- `Map.of()` 适合少量固定键值对，元素较多时可读性和参数限制都要注意。

###### 排序和比较

- `Comparable` 表示对象自身具备自然排序能力，实现 `compareTo()`。
- `Comparator` 表示外部比较器，可以在不修改类本身的情况下定义排序规则。
- `TreeSet`、`TreeMap` 默认依赖自然排序，也可以传入 `Comparator`。
- `Collections.sort(list)` 默认要求元素实现 `Comparable`，也可以传入 `Comparator`。
- 比较结果小于 0、等于 0、大于 0 分别表示小于、相等、大于。
- `TreeSet` / `TreeMap` 中比较结果为 `0` 会被认为是同一个元素或同一个 key。
- `compareTo()` / `Comparator` 的相等逻辑最好和 `equals()` 保持一致，否则集合行为容易让人误解。
- 排序字段如果可能为 `null`，比较器里要显式处理空值。

###### Android 常见集合

- `SparseArray` 是 Android 提供的 int 到对象的映射结构，可在某些场景替代 `HashMap<Integer, T>`。
- `LongSparseArray` 是 long 到对象的映射结构，可在某些场景替代 `HashMap<Long, T>`。
- `ArrayMap` 是 Android 提供的轻量 Map，适合小数据量映射。
- `LruCache` 适合做内存缓存，例如图片、解析结果、临时对象缓存。
- `CopyOnWriteArrayList` 适合读多写少的并发列表场景，写入会复制数组，成本较高。
- `BlockingQueue` 适合生产者-消费者模型，更详细内容放到并发专题。

###### 选择建议

- 只知道要用集合，不确定具体类型时，日常开发通常先考虑 `ArrayList`。
- 需要按索引访问、有序、可重复时，选 `List`。
- `List` 中不确定具体实现时，通常优先用 `ArrayList`。
- 需要频繁在队头队尾操作时，可以考虑 `ArrayDeque`。
- 需要元素唯一时，选 `Set`。
- 需要唯一且不关心顺序时，选 `HashSet`。
- 需要唯一且保留插入顺序时，选 `LinkedHashSet`。
- 需要唯一且按排序顺序遍历时，选 `TreeSet`。
- 需要 key-value 映射时，选 `Map`。
- 需要普通 key-value 存取时，选 `HashMap`。
- 需要保留插入顺序或做简单 LRU 时，选 `LinkedHashMap`。
- 需要按 key 排序遍历时，选 `TreeMap`。
- 多线程共享读写 Map 时，优先考虑 `ConcurrentHashMap`，不要直接用 `HashMap`。
- 读多写少并且需要线程安全 List 时，可以考虑 `CopyOnWriteArrayList`，但写入频繁不适合。
- 生产者-消费者任务队列可以考虑 `BlockingQueue`。
- Android 小规模 int/long key 映射可以考虑 `SparseArray` / `LongSparseArray`。
- Android 内存缓存可以考虑 `LruCache`。
- `Hashtable`、`Vector` 属于历史类，除非维护旧代码，一般不作为优先选择。

###### 常见坑

- `Set` 的不重复不是“重复元素覆盖旧元素”，而是重复添加通常失败；`Map` 相同 key 才会替换旧 value。
- `HashSet` 不保证遍历顺序，即使某次输出看起来稳定，也不要依赖这个顺序。
- `LinkedHashSet` 的插入顺序不等于队列的完整行为，它只是迭代顺序稳定。
- `TreeSet` 的唯一性和排序都依赖比较规则，比较结果为 `0` 会被认为重复。
- `HashMap` 不是线程安全的，多线程同时读写可能出现数据不一致或其他问题。
- `ConcurrentHashMap` 线程安全不代表多个操作组合起来一定是原子的。
- 集合语境中的“同步”通常指通过锁保护共享访问，不要把“异步”简单理解成多个线程随便同时访问同一个对象。
- 遍历集合时直接删除元素可能触发 `ConcurrentModificationException`。
- 自定义对象作为 `HashMap` key 或放入 `HashSet` 时，要正确重写 `equals()` 和 `hashCode()`。
- `ArrayList` 随机访问快，但频繁头部插入删除不适合。
- `LinkedList` 不是所有插入删除场景都比 `ArrayList` 快，实际还要看访问位置和数据规模。
- `TreeMap`、`TreeSet` 中元素或 key 必须可比较，否则会出现类型转换或比较异常。
- `Comparable` / `Comparator` 与 `equals()` 不一致时，`TreeSet`、`TreeMap` 的去重和查找结果可能不符合直觉。
- `HashMap` 的 key 如果参与 hash 的字段被修改，后续可能查不到这个 key。
- `Arrays.asList()` 得到的是固定长度 List，不能直接添加或删除。
- `subList()` 是视图，不是独立拷贝，使用时要小心原 List 的结构性修改。
- fail-fast 只是尽早发现并发修改问题，不是线程安全保证。
- 不可变集合不能添加、删除、修改元素，调用修改方法会抛出异常。
- `Collections.unmodifiableList()` 返回的是不可变视图，原始 list 如果被修改，这个视图看到的数据也会变化。
