### Java 泛型知识点清单

###### 内容概述

本文件记录 Java 泛型相关知识点，包括泛型基础、泛型类和泛型方法、泛型接口、类型参数和边界、通配符、类型擦除、泛型限制、泛型和数组、泛型和反射、Android 使用场景和关联面试题。

###### 使用场景

- 泛型常用于 `List<T>`、`Map<K, V>`、Adapter、Repository、BaseResponse、Callback 等通用结构。
- Retrofit、Room、JSON 解析、事件分发、缓存容器和统一响应包装中经常会遇到泛型类型传递。
- 通配符和上下界用于设计可复用 API，减少强制类型转换和类型错误。
- 类型擦除有助于理解运行时泛型判断、反射解析、序列化解析、`TypeToken` 和 `Class<T>` 传递的限制。

###### 泛型基础

- 泛型可以理解为“把类型当作参数传入代码结构”。它让类、接口、方法在定义时不绑定具体类型，在使用时再指定类型，例如 `List<String>`、`Map<String, User>`。
- 泛型解决的核心问题是类型安全和代码复用。没有泛型时，集合里放的是 `Object`，取出来需要强制转换；有泛型后，编译器可以提前检查元素类型，减少运行期 `ClassCastException`。
- 泛型主要是编译期能力。编译器会根据泛型做类型检查，并在必要位置插入类型转换；运行期大多数泛型参数会被擦除，所以泛型不是运行期万能类型信息。
- 常见类型参数命名：

| 名称 | 常见含义 |
|---|---|
| `T` | Type，普通类型 |
| `E` | Element，集合元素 |
| `K` | Key，键 |
| `V` | Value，值 |
| `R` | Result / Return，结果 |

- 泛型使用时要避免 raw type。比如 `List list = new ArrayList();` 会绕过泛型检查，编译器只能给出 unchecked 警告，类型错误可能延迟到运行期暴露。

###### 泛型类和泛型方法

- 泛型类是在类名后声明类型参数：

```java
public class Box<T> {
    private T value;

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }
}
```

- 使用泛型类时指定实际类型：

```java
Box<String> box = new Box<>();
box.setValue("hello");
String value = box.getValue();
```

- 泛型方法是在方法返回值前声明类型参数，类型参数只在这个方法范围内生效：

```java
public static <T> T first(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}
```

- 泛型方法的类型参数可以和类的类型参数无关。即使一个类不是泛型类，也可以有泛型方法。
- 泛型类上的类型参数不能直接用于静态方法或静态字段，因为静态成员属于类本身，不属于某个具体的泛型实例。静态方法如果需要泛型，应该自己声明类型参数：

```java
public static <K> K identity(K value) {
    return value;
}
```

- 泛型方法可以声明和类同名的类型参数，但这会遮蔽类上的类型参数，容易造成误解。实际代码里建议换成不同名字，或者让方法直接使用类上的类型参数。
- Java 7 以后可以使用菱形语法 `<>`，编译器根据左侧或上下文推断类型，例如 `new ArrayList<String>()` 可以简写为 `new ArrayList<>()`。
- 如果类型参数只在返回值出现，而参数里没有出现，编译器很难根据调用参数推断类型，这种 API 设计要谨慎。

###### 泛型接口

- 泛型接口是在接口名后声明类型参数，常用于回调、转换器、仓库、数据源等抽象：

```java
public interface Callback<T> {
    void onSuccess(T data);
    void onError(Throwable error);
}
```

- 实现泛型接口时有两种常见方式：一种是在实现类里继续保留类型参数，另一种是在实现类里固定具体类型。

```java
public class StringCallback implements Callback<String> {
    @Override
    public void onSuccess(String data) {
    }
}

public class BaseCallback<T> implements Callback<T> {
    @Override
    public void onSuccess(T data) {
    }
}
```

- Android 中常见的 `Adapter<T>`、`DiffUtil.ItemCallback<T>`、`Repository<T>`、`Result<T>` 都可以用泛型接口或泛型类理解。

###### 类型参数和边界

- 类型参数可以设置上界，用 `extends` 表示“只能是某个类型或其子类型”。这里的 `extends` 同时包含“继承类”和“实现接口”的含义：

```java
public static <T extends Number> double sum(List<T> list) {
    double result = 0;
    for (T item : list) {
        result += item.doubleValue();
    }
    return result;
}
```

- 上界的价值是让编译器知道 `T` 至少具备哪些能力。比如 `T extends Number` 后，可以安全调用 `doubleValue()`。
- 类型参数支持多个边界：

```java
public class Store<T extends Number & Comparable<T>> {
}
```

- 多边界里如果有类和接口，类必须写在第一个位置，后面再写接口。
- 泛型类型默认不协变。即使 `Integer` 是 `Number` 的子类，`List<Integer>` 也不是 `List<Number>` 的子类。可以把 `ArrayList<Integer>` 向上转型为 `List<Integer>`，因为集合实现类和接口之间有继承关系；但不能把 `ArrayList<Integer>` 当成 `ArrayList<Number>` 或 `List<Number>`。

###### 通配符

- `?` 表示未知类型，常用于“我不关心具体类型，只关心能不能读、能不能写”的 API 设计。
- `List<?>` 表示某种未知元素类型的列表。它可以接收 `List<String>`、`List<Integer>`、`List<User>` 等任意具体泛型列表；可以读取元素为 `Object`，但不能安全添加具体元素，除了 `null`。
- `? extends T` 是上界通配符，表示未知类型是 `T` 或 `T` 的子类型。它适合读取数据：

```java
public static double sum(List<? extends Number> list) {
    double result = 0;
    for (Number item : list) {
        result += item.doubleValue();
    }
    return result;
}
```

- `List<? extends Number>` 可以接收 `List<Integer>`、`List<Double>`、`List<Number>`。读取时可以当作 `Number` 读出来，但通常不能向里面添加 `Integer`、`Double`，因为真实列表类型未知。
- `? super T` 是下界通配符，表示未知类型是 `T` 或 `T` 的父类型。它适合写入数据：

```java
public static void addIntegers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}
```

- `List<? super Integer>` 可以接收 `List<Integer>`、`List<Number>`、`List<Object>`。它可以安全写入 `Integer`，但读取出来时只能按 `Object` 处理。
- 常用规则是 PECS：Producer Extends, Consumer Super。数据生产者用 `extends`，数据消费者用 `super`。简单记法：只读用 `extends`，要写用 `super`，既要读又要写具体类型时通常不要用通配符，直接用明确的 `List<T>`。
- 通配符和类型参数选择：如果多个参数之间需要表达“它们是同一种类型”，通常用类型参数 `<T>`；如果只是放宽某个参数的接受范围，通常用通配符。

###### 类型擦除

- Java 泛型通过类型擦除实现。编译器会把类型参数替换成边界类型，如果没有边界就替换成 `Object`；同时在必要位置插入强制类型转换，并可能生成桥接方法来保持多态。
- 例如：

```java
List<String> list = new ArrayList<>();
list.add("hello");
String value = list.get(0);
```

  编译后运行期主要看到的是普通 `List` / `ArrayList`，取值位置由编译器插入必要的类型转换。

- 类型擦除带来的直接结果：`List<String>` 和 `List<Integer>` 在运行期通常是同一个 `Class`，`new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass()` 结果为 `true`。
- 不存在 `List<String>.class` 或 `Pair<String>.class` 这种带完整泛型实参的 `Class` 字面量，只有 `List.class`、`Pair.class`。
- 类型擦除不代表所有泛型信息都完全消失。字段、方法返回值、父类签名等“声明处”的泛型信息可能保存在 class 文件的签名属性中，可以通过反射的 `Type` 系列 API 读取；但普通对象实例本身通常不知道自己当初是 `List<String>` 还是 `List<Integer>`。

###### 泛型限制

- 泛型类型参数不能直接使用基本类型，例如不能写 `List<int>`，要使用包装类型 `List<Integer>`。原因是 Java 泛型面向引用类型，类型擦除后不能用基本类型替代类型参数。
- 不能直接 `new T()`，因为类型擦除后运行期不知道 `T` 的具体构造方法。常见替代方式是传入 `Class<T>`、工厂接口或 `Supplier<T>`。

```java
public static <T> T create(Supplier<T> supplier) {
    return supplier.get();
}
```

- 不能直接使用 `obj instanceof List<String>`，因为运行期无法区分 `List<String>` 和 `List<Integer>`。最多可以判断 `obj instanceof List<?>`。
- 不能声明类型参数的静态字段，例如 `private static T value;`。静态字段属于类本身，被所有类型参数实例共享，不可能同时属于多个不同的 `T`。
- 不能通过擦除后签名相同的参数重载方法，例如 `print(List<String>)` 和 `print(List<Integer>)` 擦除后都接近 `print(List)`，会产生冲突。
- 泛型异常也有限制，泛型类不能直接或间接继承 `Throwable`，不能 `catch (T e)`；但类型参数可以出现在 `throws` 子句中。
- unchecked warning 表示编译器没有足够类型信息保证完全类型安全。遇到 `@SuppressWarnings("unchecked")` 时要尽量缩小作用范围，并确认强转是受控的。

###### 泛型和数组

- Java 数组是协变且运行期保留元素类型的，泛型是默认不协变且运行期类型擦除的。两者设计不同，所以泛型数组会有很多限制。
- 可以声明泛型数组变量，但不能直接创建具体泛型数组：

```java
List<String>[] lists;              // 可以声明
// new List<String>[10];           // 不能直接创建
```

- 不能直接 `new T[]`，因为运行期不知道 `T` 的真实类型。旧笔记里提到可以通过反射创建数组，这个思路是对的，但通常需要传入组件类型：

```java
@SuppressWarnings("unchecked")
T[] array = (T[]) Array.newInstance(componentType, size);
```

- 泛型数组相关问题本质上和类型擦除、数组运行期类型检查、堆污染有关。日常开发中优先使用 `List<T>`，除非确实需要数组。

###### 泛型和反射

- 部分反射 API 本身是泛型化的，例如 `Class<T>`、`Constructor<T>`，这样可以减少强制转换：

```java
Class<Integer> clazz = Integer.class;
Constructor<Integer> constructor = clazz.getConstructor(int.class);
Integer value = constructor.newInstance(123);
```

- `Class<T>` 常用于把运行期类型信息显式传入泛型方法，弥补类型擦除带来的限制。例如 JSON 解析、对象创建、类型转换工具常会要求传入 `Class<T>`。
- 如果类型是 `List<User>` 这类带泛型实参的复杂类型，仅传 `Class<List>` 不够，因为 `Class` 只能表达原始类型。此时常见方案是使用 `Type`、`ParameterizedType` 或框架提供的 `TypeToken` / `TypeReference`。
- 子类有时可以通过父类声明处保留的泛型信息拿到实际类型，例如 `class UserRepo extends BaseRepo<User>` 可以通过 `getGenericSuperclass()` 读取 `User`。这依赖“子类继承签名里写死了具体类型”，不代表任意对象运行期都知道自己的泛型实参。
- 常见反射泛型 API：

| API | 作用 |
|---|---|
| `getGenericType()` | 获取字段声明的泛型类型 |
| `getGenericReturnType()` | 获取方法返回值声明的泛型类型 |
| `getGenericParameterTypes()` | 获取方法参数声明的泛型类型 |
| `getGenericSuperclass()` | 获取父类声明的泛型类型 |
| `ParameterizedType` | 表示 `List<User>` 这类参数化类型 |

- 泛型和反射结合时要注意：反射能读取的是声明处保留的信息，不一定能知道某个运行期对象实例的完整泛型实参。

###### Android 使用场景和注意点

- Android 中泛型最常见的是集合、Adapter、Repository、UseCase、ViewModel 状态包装、网络响应 `BaseResponse<T>`、分页结构 `Page<T>`、回调 `Callback<T>` 等。
- Retrofit、Moshi、Gson、Room 等框架经常需要处理泛型返回值或字段类型。比如 `Call<BaseResponse<User>>`、`List<User>` 这种类型，框架通常要结合反射和泛型签名解析。
- JSON 解析时，如果只传 `List.class`，通常只能知道这是一个列表，不知道元素是 `User`。需要 `TypeToken<List<User>>`、`Types.newParameterizedType(...)` 或框架提供的等价能力。
- Kotlin 和 Java 泛型互操作时还要注意协变、逆变、可空性、`reified` 等 Kotlin 特性。Java 侧没有普通的 reified 泛型，运行期仍要靠 `Class<T>` 或 `Type` 显式传递类型。
- 不要为了“通用”滥用过深的泛型嵌套。过度泛型会让 API 难读、错误信息难懂。业务层泛型要围绕明确的数据模型和边界设计。
