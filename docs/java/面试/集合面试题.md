<a id="list-set-map-分别有什么特点"></a>
###### List Set Map 分别有什么特点

答案：

**简答：** `List` 有序可重复，`Set` 不允许重复，`Map` 保存 key-value 映射。

**展开回答：** `List` 属于 `Collection` 体系，适合保存列表数据，可以按索引访问；`Set` 也属于 `Collection`，适合去重和集合判断；`Map` 是独立体系，key 唯一、value 可重复，适合通过 key 快速查找 value。

**易错点：** `Map` 不继承 `Collection`，但它也属于 Java 集合框架的重要部分。

**关联知识点：** [Java 集合 - 集合体系](../知识点梳理/集合.md#集合体系)

<a id="arraylist-和-linkedlist-有什么区别"></a>
###### ArrayList 和 LinkedList 有什么区别

答案：

**简答：** `ArrayList` 底层是动态数组，随机访问快；`LinkedList` 底层是双向链表，按索引访问慢，但在已知节点附近插入删除更灵活。

**展开回答：** `ArrayList` 适合按下标访问、尾部追加和作为页面列表数据源，扩容时需要创建新数组并复制旧元素；`LinkedList` 每个节点保存前后引用，不要求内存连续，也实现了 `Deque`，可以当双端队列使用。

**易错点：** 不要只因为“删除多”就直接选 `LinkedList`，如果删除前还要按下标查找节点，整体成本可能并不低。实际开发中默认优先用 `ArrayList`。

**关联知识点：** [Java 集合 - List](../知识点梳理/集合.md#list)

<a id="arraylist-和-linkedlist-的时间复杂度有什么区别"></a>
###### ArrayList 和 LinkedList 的时间复杂度有什么区别

答案：

**简答：** `ArrayList` 按索引访问是 `O(1)`，尾部添加是均摊 `O(1)`，中间插入删除通常是 `O(n)`；`LinkedList` 按索引访问是 `O(n)`，已知节点附近插入删除是 `O(1)`。

**展开回答：** `ArrayList` 底层是数组，按下标可以直接计算位置，所以随机访问快；但中间插入删除会移动后续元素。`LinkedList` 底层是双向链表，节点本身插入删除只需要调整前后引用，但如果只知道索引或元素值，仍然要先遍历找到节点。

**易错点：** 不要直接说 `LinkedList` 增删一定比 `ArrayList` 快。只有已经定位到节点时，链表插入删除才体现优势；如果查找节点也算进去，经常还是 `O(n)`。

**关联知识点：** [Java 集合 - 时间复杂度和空间复杂度](../知识点梳理/集合.md#时间复杂度和空间复杂度)

<a id="hashmap-的底层结构是什么"></a>
###### HashMap 的底层结构是什么

答案：

**简答：** JDK 8 以后常见说法是数组 + 链表 + 红黑树。

**展开回答：** `HashMap` 底层是桶数组，每个桶位保存节点。put 时先根据 key 计算 hash，再定位桶位；如果桶位为空直接放入，如果发生冲突，就在桶内用链表或红黑树保存多个节点。节点中通常包含 hash、key、value、next 等信息；树化后的树节点还会有 parent、left、right、颜色等树结构信息。

**易错点：** `HashMap` 不是“一个大数组直接存所有 value”，而是通过桶位保存包含 key/value 的节点。不同 JDK 版本实现细节不同，回答时最好带上版本背景。

**关联知识点：** [Java 集合 - Map](../知识点梳理/集合.md#map)

<a id="hashmap-桶里的链表或红黑树节点存的是什么"></a>
###### HashMap 桶里的链表或红黑树节点存的是什么

答案：

**简答：** 存的是完整节点，不是单独的 value。节点里通常有 `hash`、`key`、`value`、`next`，树节点还会有树结构指针和颜色信息。

**展开回答：** `HashMap` 查找时先用 key 的 hash 定位桶位，再在桶内比较节点。桶内无论是链表还是红黑树，节点都要保存 key 和 value，因为只保存 value 就无法判断这个 value 属于哪个 key。查找逻辑可以理解为：先比较节点 hash 是否相同，再判断 `node.key == searchKey` 或 `searchKey.equals(node.key)` 是否成立，成立后才返回该节点的 value。

**易错点：** hash 相同不代表 key 一定相等，因为哈希冲突允许存在；必须继续用 `equals()` 判断。相同 key 再次 `put()` 是替换旧 value，不是新增一个重复 key。

**关联知识点：** [Java 集合 - 底层数据结构](../知识点梳理/集合.md#底层数据结构)

<a id="hashmap-为什么平均复杂度是-o1"></a>
###### HashMap 为什么平均复杂度是 O(1)

答案：

**简答：** 因为 `HashMap` 通过 hash 直接定位桶位，hash 分布均匀时，桶内元素很少，所以按 key 查找、添加、删除平均接近 `O(1)`。

**展开回答：** `HashMap` 会先根据 key 计算 hash，再通过桶数组定位位置。如果 key 分布比较均匀，大多数桶里只有很少元素，定位桶位后只需要比较少量节点。但如果大量 key 落到同一个桶，就会发生哈希冲突，桶内查找会变慢；JDK 8 以后满足条件时会把长链表树化为红黑树，把冲突严重时的桶内查找改善到接近 `O(log n)`。

**易错点：** `HashMap` 不是任何情况下都绝对 `O(1)`。平均 `O(1)`依赖 hash 分布，扩容、冲突、树化都会影响某一次操作的实际成本。

**关联知识点：** [Java 集合 - 时间复杂度和空间复杂度](../知识点梳理/集合.md#时间复杂度和空间复杂度)

<a id="hashmap-为什么容量通常是-2-的幂"></a>
###### HashMap 为什么容量通常是 2 的幂

答案：

**简答：** 为了通过位运算快速定位桶位，并让扩容迁移规则更简单。

**展开回答：** 当容量是 2 的幂时，`hash & (n - 1)` 可以等价于取模，但性能更好。扩容后，节点要么留在原位置，要么移动到原位置加旧容量的位置，迁移规则相对清晰。

**易错点：** 容量是 2 的幂不代表没有哈希冲突，只是有助于定位和分布。

**关联知识点：** [Java 集合 - Map](../知识点梳理/集合.md#map)

<a id="hashmap-扩容和树化大概发生在什么时候"></a>
###### HashMap 扩容和树化大概发生在什么时候

答案：

**简答：** 元素数量超过阈值时扩容；JDK 8 中桶内链表足够长且数组容量足够大时可能树化。

**展开回答：** 阈值通常由容量和负载因子决定，默认负载因子常见是 `0.75`。JDK 8 常见说法是链表节点达到 `8` 且数组容量至少 `64` 时可能转红黑树；如果容量还小，可能优先扩容。

**易错点：** 树化、退化阈值是实现细节，面试中要说明“JDK 8 常见实现”，不要说成所有版本绝对不变。

**关联知识点：** [Java 集合 - Map](../知识点梳理/集合.md#map)

<a id="hashmap-为什么要重写-equals-和-hashcode"></a>
###### HashMap 为什么要重写 equals 和 hashCode

答案：

**简答：** 因为 `HashMap` 先用 `hashCode()` 定位桶，再用 `equals()` 判断 key 是否相等。

**展开回答：** 如果两个对象逻辑相等，`equals()` 返回 true，那么它们的 `hashCode()` 必须相同，否则可能落到不同桶里，导致查询失败。hash 相同只能说明可能相等，还要继续用 `equals()` 判断，因为哈希冲突允许存在。

**易错点：** key 放入 `HashMap` 后，不要修改参与 `equals()` / `hashCode()` 的字段，否则后续可能查不到。

**关联知识点：** [Java 集合 - Map](../知识点梳理/集合.md#map)

<a id="hashset-如何保证元素不重复"></a>
###### HashSet 如何保证元素不重复

答案：

**简答：** `HashSet` 底层通常基于 `HashMap`，元素作为 key 保存。

**展开回答：** 添加元素时，`HashSet` 会借助 `HashMap` 的 key 唯一性判断是否已经存在。对于自定义对象，唯一性依赖 `hashCode()` 和 `equals()`。

**易错点：** `HashSet` 遇到重复元素通常是添加失败，不是覆盖旧元素；`Map` 相同 key 才会替换 value。

**关联知识点：** [Java 集合 - Set](../知识点梳理/集合.md#set)

<a id="hashset-linkedhashset-treeset-有什么区别"></a>
###### HashSet LinkedHashSet TreeSet 有什么区别

答案：

**简答：** `HashSet` 不保证顺序，`LinkedHashSet` 保留插入顺序，`TreeSet` 按排序规则有序。

**展开回答：** `HashSet` 基于哈希表，查找效率高但遍历顺序不稳定；`LinkedHashSet` 在哈希表基础上维护链表，迭代顺序通常是插入顺序；`TreeSet` 底层常见是红黑树，依赖 `Comparable` 或 `Comparator` 排序。

**易错点：** `LinkedHashSet` 的“有序”是迭代顺序稳定，不等于完整队列行为；`TreeSet` 判断重复看比较结果是否为 0。

**关联知识点：** [Java 集合 - Set](../知识点梳理/集合.md#set)

<a id="hashmap-和-hashtable-有什么区别"></a>
###### HashMap 和 Hashtable 有什么区别

答案：

**简答：** `HashMap` 非线程安全，允许 null；`Hashtable` 方法同步，不允许 null，属于较老的集合类。

**展开回答：** `Hashtable` 底层也属于哈希表结构，通常可以理解为数组 + 链表；JDK 8 以后的 `HashMap` 常见说法是数组 + 链表 + 红黑树，冲突严重且满足条件时桶内链表可能树化。`Hashtable` 大多数公开方法使用 `synchronized`，线程安全但锁粒度粗，效率较低；`HashMap` 更常用于普通单线程或外部同步场景。并发场景通常优先考虑 `ConcurrentHashMap`。

**易错点：** 维护旧代码可能还会遇到 `Hashtable`，新代码通常不优先选择它。

**关联知识点：** [Java 集合 - Map](../知识点梳理/集合.md#map)

<a id="concurrenthashmap-和-hashmap-有什么区别"></a>
###### ConcurrentHashMap 和 HashMap 有什么区别

答案：

**简答：** `HashMap` 不是线程安全的，`ConcurrentHashMap` 面向并发访问设计。

**展开回答：** 多线程同时读写共享 Map 时，`HashMap` 可能出现数据不一致等问题；`ConcurrentHashMap` 提供并发安全能力，具体实现机制和 JDK 版本有关。

**易错点：** `ConcurrentHashMap` 线程安全不代表复合业务操作天然原子，例如“先判断再 put”应该考虑 `putIfAbsent()` 等原子方法。

**关联知识点：** [Java 集合 - Map](../知识点梳理/集合.md#map)

<a id="collectionssynchronizedmap-和-concurrenthashmap-有什么区别"></a>
###### Collections.synchronizedMap 和 ConcurrentHashMap 有什么区别

答案：

**简答：** `Collections.synchronizedMap()` 是给普通 Map 包一层同步锁；`ConcurrentHashMap` 是专门为并发访问设计的 Map。

**展开回答：** 同步包装通常锁粒度更粗，迭代时还需要外部手动同步；`ConcurrentHashMap` 并发能力更强，更适合多线程高频访问场景。

**易错点：** 二者都不能让多个业务步骤自动变成原子操作。

**关联知识点：** [Java 集合 - Collections 工具类](../知识点梳理/集合.md#collections-工具类)

<a id="arraysaslist-有哪些坑"></a>
###### Arrays.asList 有哪些坑

答案：

**简答：** 它返回固定长度 List，不能 `add()` / `remove()`。

**展开回答：** `Arrays.asList()` 返回的 List 背后关联原数组，可以 `set()` 修改元素，但不能改变长度。传入基本类型数组时，比如 `int[]`，会得到一个只包含该数组对象的 List。

**易错点：** `Arrays.asList(new int[]{1, 2, 3})` 的大小是 1，不是 3。

**关联知识点：** [Java 集合 - List](../知识点梳理/集合.md#list)

<a id="sublist-是新集合还是原集合视图"></a>
###### subList 是新集合还是原集合视图

答案：

**简答：** `subList()` 返回的是原 List 的视图，不是独立新集合。

**展开回答：** 修改 `subList()` 会影响原 List；原 List 发生结构性修改后，继续操作旧 `subList()` 可能抛出异常。需要独立集合时，可以用 `new ArrayList<>(list.subList(...))`。

**易错点：** 不要把 `subList()` 当成深拷贝或独立集合。

**关联知识点：** [Java 集合 - List](../知识点梳理/集合.md#list)

<a id="treeset-的比较器和-equals-不一致会怎样"></a>
###### TreeSet 的比较器和 equals 不一致会怎样

答案：

**简答：** `TreeSet` 根据比较结果判断排序和唯一性，比较结果为 `0` 会被认为重复。

**展开回答：** 如果 `Comparator` 或 `compareTo()` 认为两个对象相等，但 `equals()` 不相等，`TreeSet` 仍可能只保留一个元素。`TreeMap` 的 key 也有类似问题。

**易错点：** 设计排序规则时，比较器的相等逻辑最好和 `equals()` 保持一致。

**关联知识点：** [Java 集合 - 排序和比较](../知识点梳理/集合.md#排序和比较)

<a id="iterator-的作用是什么"></a>
###### Iterator 的作用是什么

答案：

**简答：** `Iterator` 提供统一遍历模型，让调用方不用关心集合底层结构。

**展开回答：** 不同集合底层可能是数组、链表、哈希表或树，但都可以通过迭代器遍历。遍历时需要删除当前元素，优先用 `Iterator.remove()`。

**易错点：** 遍历过程中直接调用集合自身 `remove()` 可能触发 `ConcurrentModificationException`。

**关联知识点：** [Java 集合 - Iterator](../知识点梳理/集合.md#iterator)

答案：

**展开回答：** `Collection` 表示一组元素，是 `List`、`Set`、`Queue` 的父接口；`Collections` 提供大量静态工具方法，比如排序、洗牌、空集合、不可变包装、同步包装等。

**易错点：** `Map` 不继承 `Collection`，但 `Collections` 工具类里也有操作 Map 的方法。

<a id="collectionsunmodifiablelist-和真正不可变集合有什么区别"></a>
###### Collections.unmodifiableList 和真正不可变集合有什么区别

答案：

**简答：** `unmodifiableList()` 返回的是不可变视图，不是独立副本。

**展开回答：** 通过这个视图不能直接修改集合，但原始 List 如果被修改，视图看到的数据也会变化。真正需要隔离时，要先复制一份，再包装或使用不可变集合工厂。

**易错点：** `unmodifiableList()` 不是深拷贝。

<a id="treemap-和-hashmap-的复杂度有什么区别"></a>
###### TreeMap 和 HashMap 的复杂度有什么区别

答案：

**简答：** `HashMap` 平均查找、添加、删除接近 `O(1)`，但不保证有序；`TreeMap` 查找、添加、删除是 `O(log n)`，但可以按 key 的排序顺序遍历。

**展开回答：** `HashMap` 底层主要依赖哈希表，优势是按 key 快速定位 value；`TreeMap` 底层常见是红黑树，优势是 key 有序、支持范围查找和顺序遍历。选择时不要只看复杂度，还要看是否需要排序能力。

**易错点：** `TreeMap` 不是为了替代 `HashMap` 的普通查找场景。普通 key-value 映射优先考虑 `HashMap`；需要 key 有序、范围查询、最近 key 等能力时再考虑 `TreeMap`。

**关联知识点：** [Java 集合 - 时间复杂度和空间复杂度](../知识点梳理/集合.md#时间复杂度和空间复杂度)

<a id="priorityqueue-为什么不是普通-fifo-队列"></a>
###### PriorityQueue 为什么不是普通 FIFO 队列

答案：

**简答：** `PriorityQueue` 是优先级队列，不按先进先出出队，而是按自然排序或比较器决定优先级。

**展开回答：** `PriorityQueue` 底层常见是堆结构，逻辑上可以理解成一棵完全二叉树，堆顶保存当前优先级最高或最小的元素。`peek()` 查看堆顶通常是 `O(1)`，`offer()` 和 `poll()` 需要调整堆结构，通常是 `O(log n)`。它适合任务优先级、取最小值/最大值、Top K 等场景。

**易错点：** `PriorityQueue` 的遍历顺序不等于出队顺序，也不保证整体有序；它只保证每次 `poll()` 能按优先级取出当前应该出队的元素。

**关联知识点：** [Java 集合 - 底层数据结构](../知识点梳理/集合.md#底层数据结构)

<a id="android-中-sparsearray-arraymap-lrucache-分别适合什么场景"></a>
###### Android 中 SparseArray ArrayMap LruCache 分别适合什么场景

答案：

**简答：** `SparseArray` 适合小规模 int key 映射，`ArrayMap` 适合小规模 key-value 映射，`LruCache` 适合内存缓存。

**展开回答：** `SparseArray` 可以减少 `HashMap<Integer, T>` 中 Integer 装箱开销；`ArrayMap` 是轻量 Map，大数据量或频繁修改不一定更合适；`LruCache` 会按最近最少使用策略淘汰数据，常用于图片、解析结果等缓存。

**易错点：** Android 特有集合不是任何场景都比 Java 标准集合快，要看数据量、访问模式和可读性。
