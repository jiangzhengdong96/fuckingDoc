###### ArrayList 和 LinkedList 有什么区别

答案：

**简答：** `ArrayList` 基于数组，随机访问快；`LinkedList` 基于链表，插入删除更灵活。

**展开回答：** `ArrayList` 适合按下标访问和尾部追加；`LinkedList` 更适合频繁在链表节点附近插入删除，但随机访问成本高。

**易错点：** 实际开发中默认优先用 `ArrayList`，不要只因为“删除多”就直接选 `LinkedList`。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### HashMap 为什么容量通常是 2 的幂

答案：

**简答：** 主要是为了通过位运算快速定位桶位，并让元素分布更均匀。

**展开回答：** 当容量是 2 的幂时，`hash & (n - 1)` 可以等价于取模，但性能更好。扩容后元素要么留在原位置，要么移动到原位置加旧容量的位置，迁移规则也更简单。

**易错点：** 容量是 2 的幂不代表没有哈希冲突，只是有助于定位和分布。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### HashMap 扩容和树化大概发生在什么时候

答案：

**简答：** 元素数量超过阈值会扩容；JDK 8 中桶内链表足够长且数组容量足够大时可能树化。

**展开回答：** 阈值通常由容量和负载因子决定，默认负载因子常见是 `0.75`。JDK 8 常见说法是链表节点达到 `8` 且容量至少 `64` 时可能转红黑树，否则可能优先扩容。

**易错点：** 树化条件和退化条件属于实现细节，面试回答最好带上 JDK 版本背景。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### Arrays.asList 有哪些坑

答案：

**简答：** 它返回的是固定长度 List，不能 `add()` / `remove()`。

**展开回答：** `Arrays.asList()` 返回的 List 背后仍然关联原数组，可以 `set()` 修改元素，但不能改变长度。传入基本类型数组时，比如 `int[]`，会得到一个只包含该数组对象的 List。

**易错点：** `Arrays.asList(new int[]{1, 2, 3})` 的大小是 1，不是 3。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### subList 是新集合还是原集合视图

答案：

**简答：** `subList()` 返回的是原 List 的视图，不是独立新集合。

**展开回答：** 修改 `subList()` 会影响原 List；原 List 发生结构性修改后，继续操作旧 `subList()` 可能抛出异常。需要独立集合时，可以用 `new ArrayList<>(list.subList(...))`。

**易错点：** 不要把 `subList()` 当成深拷贝或独立集合。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### TreeSet 的比较器和 equals 不一致会怎样

答案：

**简答：** `TreeSet` 主要根据比较结果判断排序和唯一性，比较结果为 `0` 会被认为是重复元素。

**展开回答：** 如果 `Comparator` 或 `compareTo()` 认为两个对象相等，但 `equals()` 不相等，`TreeSet` 仍可能只保留一个元素。这会导致去重行为和普通 `Set` 直觉不一致。

**易错点：** `TreeMap` 的 key 也有类似问题。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### Collections.synchronizedMap 和 ConcurrentHashMap 有什么区别

答案：

**简答：** `Collections.synchronizedMap()` 是给普通 Map 包一层同步锁；`ConcurrentHashMap` 是专门为并发访问设计的 Map。

**展开回答：** 同步包装通常锁粒度更粗，迭代时还需要外部手动同步。`ConcurrentHashMap` 支持更好的并发访问，但复合操作仍然要关注原子性。

**易错点：** 线程安全集合不等于业务上的多个操作自动原子。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### HashMap 的底层结构是什么

答案：

**简答：** 常见说法是数组 + 链表 + 红黑树。

**展开回答：** key 经过 hash 定位桶位，冲突时形成链表；链表过长且容量满足条件后会树化，提高查询效率。

**易错点：** 不同 JDK 版本实现细节不同，面试时要说明版本背景。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### HashMap 为什么要重写 equals 和 hashCode

答案：

**简答：** 因为 HashMap 通过 hashCode 定位桶，再用 equals 判断 key 是否相等。

**展开回答：** 如果只重写 `equals` 不重写 `hashCode`，逻辑相等的对象可能落到不同桶，导致查询失败。

**易错点：** 相等对象必须有相同 hashCode，但相同 hashCode 的对象不一定相等。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### HashSet 如何保证元素不重复

答案：

**简答：** `HashSet` 底层通常基于 `HashMap`，元素作为 key 存储。

**展开回答：** 判断是否重复依赖元素的 `hashCode` 和 `equals`。

**易错点：** 自定义对象放入 `HashSet` 也要正确重写 `equals` 和 `hashCode`。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)

###### ConcurrentHashMap 和 HashMap 有什么区别

答案：

**简答：** `HashMap` 不是线程安全的，`ConcurrentHashMap` 支持并发访问。

**展开回答：** 多线程读写共享 Map 时，优先考虑 `ConcurrentHashMap`。具体并发控制机制和 JDK 版本有关。

**易错点：** `ConcurrentHashMap` 线程安全不代表复合业务操作天然原子。

**关联知识点：** [Java 集合](../知识点梳理/集合.md)
