<a id="枚举相比常量有什么优势"></a>
###### 枚举相比常量有什么优势

答案：

- 枚举能表达一组固定取值，并且有类型约束，调用方不能传入枚举集合之外的值。
- 相比字符串或 int 常量，枚举更可读、更安全，也更适合配合 `switch`、字段、方法和策略行为。
- 枚举可以把状态值和对应文案、业务 code、处理逻辑放在一起，减少散落的常量和判断。
- 如果取值会由服务端动态扩展，或者客户端不应该写死全集，就不一定适合使用枚举。

关联知识点：[枚举基础](../知识点梳理/枚举.md#枚举基础)

<a id="枚举的本质是什么"></a>
###### 枚举的本质是什么

答案：

- 枚举类本质上继承自 `java.lang.Enum`，每个枚举常量都是该枚举类型的固定实例。
- 枚举不能再继承其他类，但可以实现接口。
- 枚举构造方法不能被外部调用，外部不能 `new` 一个枚举实例。
- 枚举适合有限集合，不适合运行时动态增加的类型集合。

关联知识点：[枚举基础](../知识点梳理/枚举.md#枚举基础)

<a id="枚举能不能有字段和构造方法"></a>
###### 枚举能不能有字段和构造方法

答案：

- 可以。枚举可以有字段、构造方法、普通方法、静态方法，也可以实现接口。
- 枚举构造方法只能是 private 语义，用于给每个枚举常量初始化字段。
- 枚举字段建议设计为不可变，例如 `private final`，避免共享枚举实例被修改后造成状态污染。
- 如果每个枚举常量行为不同，还可以定义抽象方法，让每个常量分别实现。

关联知识点：[枚举字段和方法](../知识点梳理/枚举.md#枚举字段和方法)

<a id="为什么不建议持久化-ordinal"></a>
###### 为什么不建议持久化 ordinal

答案：

- `ordinal()` 表示枚举常量的声明顺序，从 0 开始。
- 如果后续调整枚举顺序、在中间插入新枚举或删除枚举，旧数据里的 ordinal 就会被解释成错误含义。
- 数据库、网络协议、本地持久化都不建议保存 ordinal。
- 更推荐显式定义稳定 `code` 字段，持久化 code，再通过查找方法转换成枚举。

关联知识点：[常用 API](../知识点梳理/枚举.md#常用-api)

<a id="enumset-和-enummap-有什么用"></a>
###### EnumSet 和 EnumMap 有什么用

答案：

- `EnumSet` 是专门给枚举设计的 Set，适合保存一组选项、权限或标记位，内部通常比普通 Set 更紧凑高效。
- `EnumMap` 是 key 为枚举的 Map，内部按枚举顺序建立数组索引，比普通 `HashMap` 更适合枚举 key。
- 如果集合元素或 Map key 明确是枚举，优先考虑 `EnumSet` / `EnumMap`。
- 它们适合固定枚举类型，不适合动态 key。

关联知识点：[EnumSet 和 EnumMap](../知识点梳理/枚举.md#enumset-和-enummap)

<a id="枚举单例有什么特点"></a>
###### 枚举单例有什么特点

答案：

- 枚举单例写法简单，由 JVM 保证枚举常量唯一。
- 枚举天然支持序列化时保持单例语义，也能避免常规反射方式创建新实例。
- 它适合简单、无继承需求、生命周期稳定的单例。
- Android 中如果单例持有 `Context`、需要依赖注入、测试替换或生命周期管理，要谨慎使用枚举单例，避免内存泄漏和可测试性问题。

关联知识点：[枚举单例](../知识点梳理/枚举.md#枚举单例)

<a id="枚举序列化要注意什么"></a>
###### 枚举序列化要注意什么

答案：

- 枚举天然实现 `Serializable`，反序列化后仍然回到同一个枚举常量实例。
- Java 序列化枚举主要依赖枚举常量名称，不是普通对象字段序列化。
- 修改枚举常量名称可能导致旧数据无法反序列化；新增常量通常不影响旧常量读取。
- 不要用 `ordinal()` 作为长期存储值，应该使用显式 code 或稳定字符串。

关联知识点：[枚举和序列化](../知识点梳理/枚举.md#枚举和序列化)

<a id="android-中枚举和-intdef-怎么选"></a>
###### Android 中枚举和 IntDef 怎么选

答案：

- 普通业务代码优先考虑枚举，因为可读性和类型安全更好。
- `@IntDef` / `@StringDef` 适合 Android SDK 风格 API、底层库、极高频路径或希望运行时仍然是 int / String 的场景。
- 早期 Android 常说避免枚举，主要是历史上的包体、内存和性能考虑。现代项目不要机械回避，应该结合业务层级和性能测量。
- 和服务端交互时，不管用枚举还是 `IntDef`，都要处理未知值，避免服务端新增类型导致客户端崩溃。

关联知识点：[Android 使用场景和注意点](../知识点梳理/枚举.md#android-使用场景和注意点)
