## start 和 run 有什么区别

**简答：** `start()` 会启动新线程，`run()` 只是普通方法调用。

**展开回答：** 调用 `start()` 后，线程进入可运行状态，由 JVM 调度执行 `run()`；直接调用 `run()` 不会产生新线程。

**易错点：** 一个线程对象不能重复调用 `start()`。

**关联知识点：** [Java 线程](../知识点梳理/线程.md)

## Java 线程有哪些状态

**简答：** 常见状态包括 `NEW`、`RUNNABLE`、`BLOCKED`、`WAITING`、`TIMED_WAITING`、`TERMINATED`。

**展开回答：** 线程从新建开始，启动后进入可运行状态，可能因为锁、等待、限时等待进入不同阻塞状态，执行结束后终止。

**易错点：** `RUNNABLE` 在 Java 层同时包含就绪和运行中。

**关联知识点：** [Java 线程](../知识点梳理/线程.md)

## sleep 和 wait 有什么区别

**简答：** `sleep()` 是 Thread 方法，不释放锁；`wait()` 是 Object 方法，会释放对象锁。

**展开回答：** `wait()` 必须在同步代码块或同步方法中调用，通常配合 `notify/notifyAll` 使用。

**易错点：** `sleep()` 不用于线程通信。

**关联知识点：** [Java 线程](../知识点梳理/线程.md)

## synchronized 锁的是什么

**简答：** `synchronized` 锁的是对象监视器。

**展开回答：** 普通同步方法锁当前对象；静态同步方法锁 Class 对象；同步代码块锁括号里指定的对象。

**易错点：** 锁对象不同就不能互斥。

**关联知识点：** [Java 线程](../知识点梳理/线程.md)

## volatile 能保证原子性吗

**简答：** 不能。

**展开回答：** `volatile` 主要保证可见性和禁止部分重排序，不保证复合操作原子性。

**易错点：** `i++` 不是原子操作，即使用 volatile 修饰也不安全。

**关联知识点：** [Java 线程](../知识点梳理/线程.md)
