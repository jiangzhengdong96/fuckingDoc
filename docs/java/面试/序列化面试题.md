###### 什么是序列化和反序列化

答案：

- 序列化是把对象状态转换成可保存或传输的数据形式，例如字节流、JSON、Protocol Buffers 等。
- 反序列化是把这些数据重新恢复成对象。
- Java 原生序列化通常指 `ObjectOutputStream` / `ObjectInputStream` 配合 `Serializable` 把对象转换成二进制对象流。
- 序列化保存的是对象实例状态，不是 class 定义本身。反序列化时本地仍然要有对应类。

关联知识点：[序列化基础](../知识点梳理/序列化.md#序列化基础)

###### Serializable 为什么是标记接口

答案：

- `Serializable` 没有需要实现的方法，它只是标记这个类允许被 Java 原生序列化机制处理。
- 真正的序列化逻辑由 `ObjectOutputStream` / `ObjectInputStream` 和 JVM 序列化机制完成。
- 如果一个对象没有实现 `Serializable`，直接用 Java 原生对象流序列化时会抛出 `NotSerializableException`。
- 字段引用的对象也要能被序列化，除非该字段是 `transient` 或不参与对象实例状态。

关联知识点：[Serializable](../知识点梳理/序列化.md#serializable)

###### transient 有什么作用

答案：

- `transient` 用来修饰字段，表示这个字段不参与 Java 原生序列化。
- 反序列化后，`transient` 字段会恢复为类型默认值，例如对象为 `null`，数字为 `0`，布尔为 `false`。
- 常见用途是排除密码、token、临时缓存、运行期上下文、文件句柄、Socket、数据库连接等不应该或不能被序列化的字段。
- `transient` 主要影响 Java 原生序列化，不代表所有 JSON、Parcelable、Room 等框架都会按同样规则处理。

关联知识点：[transient](../知识点梳理/序列化.md#transient)

###### serialVersionUID 有什么作用

答案：

- `serialVersionUID` 是序列化版本号，用来判断序列化数据和当前类定义是否兼容。
- 如果没有显式声明，JVM 会根据类结构自动计算。类结构变化后计算值可能改变，反序列化旧数据时可能抛出 `InvalidClassException`。
- 需要持久化或跨版本传输的 `Serializable` 类建议显式声明 `serialVersionUID`。
- `serialVersionUID` 相同不代表一定兼容，只是允许反序列化继续尝试。字段类型变化、类层级变化等仍然可能导致问题。

关联知识点：[serialVersionUID](../知识点梳理/序列化.md#serialversionuid)

###### 反序列化会调用构造方法吗

答案：

- 对 `Serializable` 对象本身来说，反序列化不会像 `new` 一样调用它的普通构造方法。
- 对于第一个不可序列化父类，反序列化过程会调用它的无参构造方法。
- 因为构造方法可能不执行，所以依赖构造方法初始化的 `transient` 字段、缓存对象、运行期资源，要在 `readObject()` 或业务初始化逻辑里重新建立。
- 这也是为什么反序列化对象要做合法性校验，不能默认认为它一定经过了正常构造流程。

关联知识点：[反序列化和兼容性](../知识点梳理/序列化.md#反序列化和兼容性)

###### Serializable 和 Parcelable 有什么区别

答案：

- `Serializable` 是 Java 原生序列化机制，使用简单，实现标记接口即可，但性能一般、版本兼容和安全问题更多。
- `Parcelable` 是 Android 的对象扁平化机制，主要用于 `Intent`、`Bundle`、Binder IPC 等 Android 运行时数据传递。
- `Parcelable` 需要明确写入和读取字段，代码量更多，但在 Android 组件传递里通常更高效、可控。
- `Parcel` 不是稳定的长期持久化格式，不适合当文件格式或网络协议。

关联知识点：[Parcelable 对比](../知识点梳理/序列化.md#parcelable-对比)

###### 为什么不建议反序列化不可信数据

答案：

- Java 原生反序列化会根据对象流恢复对象图，过程中可能触发类加载、对象恢复、自定义 `readObject()` 等逻辑。
- 如果数据来自不可信来源，攻击者可能构造恶意对象流，利用反序列化链触发危险代码路径。
- 实际项目中不要直接反序列化外部输入。跨端传输优先使用 JSON、Protocol Buffers 等明确数据格式，并做字段校验。
- 如果确实要使用 Java 原生反序列化，也要限制输入来源、控制可反序列化类型、做好校验和异常处理。

关联知识点：[反序列化和兼容性](../知识点梳理/序列化.md#反序列化和兼容性)

###### Java 原生序列化适合做网络协议吗

答案：

- 通常不适合。
- Java 原生序列化是 Java 生态内部对象流格式，二进制不直观，跨语言差，版本兼容复杂，也存在安全风险。
- 网络接口更推荐 JSON、Protocol Buffers、FlatBuffers 等明确协议格式，字段含义、版本演进、跨端解析都更可控。
- Android 业务里一般是网络层 JSON / Protobuf，本地页面传递用 `Parcelable` 或只传 id，本地持久化用数据库、DataStore 或明确文件格式。

关联知识点：[序列化基础](../知识点梳理/序列化.md#序列化基础)
