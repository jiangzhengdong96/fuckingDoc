###### 什么是反射解决了什么问题

答案：

**简答：** 反射是在运行期通过 `Class`、`Constructor`、`Field`、`Method` 等 API 获取类信息、创建对象、访问字段和调用方法的能力。

**展开回答：** 普通调用是在编译期就知道类型和方法，反射是在运行期根据类信息决定要访问什么。它常用于框架层，例如注解扫描、对象创建、依赖注入、序列化、路由、动态代理和插件化。

**易错点：** 反射不是业务代码的默认选择。已知类型时直接调用更清晰、更安全，也更容易被编译器检查。

**关联知识点：** [Java 反射 - 反射基础和 Class 对象](../知识点梳理/反射.md#反射基础和-class-对象)

###### 获取 Class 对象有哪些方式

答案：

**简答：** 常见方式有 `类名.class`、`对象.getClass()`、`Class.forName("完整类名")`。

**展开回答：** `String.class` 适合编译期已知类型；`obj.getClass()` 适合已经有对象实例时获取真实运行时类型；`Class.forName()` 适合通过字符串类名动态加载类，例如配置化、插件化或旧 JDBC 写法。

**易错点：** `Class.forName()` 类名写错会抛出 `ClassNotFoundException`，并且默认会触发类初始化；`类名.class` 更安全直接。

**关联知识点：** [Java 反射 - 获取类信息](../知识点梳理/反射.md#获取类信息)

###### Class.forName 和 类名.class 有什么区别

答案：

**简答：** `类名.class` 是编译期明确引用类型；`Class.forName()` 是运行期根据字符串加载类。

**展开回答：** `类名.class` 不需要写完整类名字符串，编译器能检查类型是否存在；`Class.forName()` 更动态，但类名错误只能在运行期暴露。`Class.forName(String)` 默认会初始化类，如果只想加载但不初始化，可以使用带 `initialize` 参数的重载方法。

**易错点：** 不要把 `Class.forName()` 当成普通获取 `Class` 的唯一方式。能用 `类名.class` 时，通常优先用它。

**关联知识点：** [Java 反射 - 获取类信息](../知识点梳理/反射.md#获取类信息)

###### Class 对象和 ClassLoader 有什么关系

答案：

**简答：** `Class` 对象由类加载器加载或定义类时产生，同名类如果由不同 `ClassLoader` 加载，可能是不同的运行时类型。

**展开回答：** 判断一个 Java 类型是否相同，不能只看包名和类名，还要看加载它的类加载器。插件化、热修复、多 Dex、容器隔离等场景下，同名类可能由不同加载器加载，得到不同的 `Class` 对象，强转时也可能出现 `ClassCastException`。

**易错点：** `Class.forName(String)` 默认会触发类初始化；如果只想加载不初始化，可以使用 `Class.forName(name, false, classLoader)` 或合适的 `ClassLoader.loadClass()`。

**关联知识点：** [Java 反射 - 动态加载和类初始化](../知识点梳理/反射.md#动态加载和类初始化)

###### getMethod 和 getDeclaredMethod 有什么区别

答案：

**简答：** `getMethod()` 获取 public 方法，并包含继承来的 public 方法；`getDeclaredMethod()` 获取当前类声明的方法，包含 private、protected、默认访问级别和 public，但不包含父类方法。

**展开回答：** 字段和构造方法也有类似区别，例如 `getField()` / `getDeclaredField()`、`getConstructor()` / `getDeclaredConstructor()`。如果要拿当前类的私有成员，通常使用 `getDeclaredXxx()`；如果要拿继承来的 public 成员，可以使用 `getXxx()`。

**易错点：** `getDeclaredMethod()` 不会自动向父类查找。如果需要扫描父类私有字段或方法，要沿着 `getSuperclass()` 递归处理。

**关联知识点：** [Java 反射 - 获取类信息](../知识点梳理/反射.md#获取类信息)

###### 如何通过反射创建对象

答案：

**简答：** 推荐通过 `Constructor` 创建对象，例如 `clazz.getDeclaredConstructor(...).newInstance(...)`。

**展开回答：**

```java
Class<User> clazz = User.class;
Constructor<User> constructor = clazz.getDeclaredConstructor(String.class, int.class);
User user = constructor.newInstance("Tom", 18);
```

`getConstructor()` 只能拿 public 构造方法，`getDeclaredConstructor()` 可以拿当前类声明的构造方法。如果构造方法不是 public，还需要在允许的情况下调用 `setAccessible(true)`。

**易错点：** 反射创建对象不是绕过构造方法，最终仍然会调用目标构造方法；构造方法内部抛出的异常会被 `InvocationTargetException` 包装。

**关联知识点：** [Java 反射 - 构造方法和对象创建](../知识点梳理/反射.md#构造方法和对象创建)

###### 为什么不推荐使用 Class.newInstance

答案：

**简答：** `Class.newInstance()` 只能调用 public 无参构造方法，并且从 Java 9 开始已经被标记为 deprecated，推荐使用 `getDeclaredConstructor().newInstance()`。

**展开回答：** `Class.newInstance()` 表达能力弱，不能直接选择有参构造方法，也不方便处理构造方法内部异常。`Constructor.newInstance()` 能明确选择构造方法，异常语义也更清晰。

**易错点：** 如果目标类没有 public 无参构造方法，`Class.newInstance()` 会失败。旧笔记里“通过 Class.newInstance 可以创建类实例”这个说法要加上限制条件。

**关联知识点：** [Java 反射 - 构造方法和对象创建](../知识点梳理/反射.md#构造方法和对象创建)

###### 反射怎么访问字段和调用方法

答案：

**简答：** 字段通过 `Field.get()` / `Field.set()`，方法通过 `Method.invoke()`。

**展开回答：**

```java
Field field = User.class.getDeclaredField("name");
field.setAccessible(true);
Object value = field.get(user);

Method method = User.class.getDeclaredMethod("setName", String.class);
method.setAccessible(true);
method.invoke(user, "Jerry");
```

调用实例方法时，`invoke()` 第一个参数是目标对象；调用静态方法时，第一个参数可以传 `null`。参数类型必须和方法签名匹配。

**易错点：** `Method.invoke()` 返回的是方法返回值；如果目标方法内部抛异常，会被包装成 `InvocationTargetException`，需要看 `getCause()`。

**关联知识点：** [Java 反射 - 字段和方法调用](../知识点梳理/反射.md#字段和方法调用)

###### setAccessible true 的作用和风险是什么

答案：

**简答：** `setAccessible(true)` 是请求关闭 Java 语言访问检查，用来访问非 public 成员，但它不是万能通行证。

**展开回答：** 在传统 Java 里，`setAccessible(true)` 常用于访问 private 构造方法、字段或方法。现代 Java 受模块系统限制，Android 也有隐藏 API 限制，访问仍可能失败。Java 9 以后还可以用 `trySetAccessible()` 判断是否能成功打开访问。

**易错点：** 反射能访问不等于应该访问。频繁访问私有成员会破坏封装，也容易因为系统版本、混淆或模块边界变化导致运行期问题。

**关联知识点：** [Java 反射 - 字段和方法调用](../知识点梳理/反射.md#字段和方法调用)

###### 反射和注解是什么关系

答案：

**简答：** 运行期注解通常通过反射读取，反射负责拿到类、字段、方法和参数上的注解信息。

**展开回答：** 注解如果要在运行期被反射读取，必须声明 `@Retention(RetentionPolicy.RUNTIME)`。常见 API 有 `getAnnotation()`、`getDeclaredAnnotations()`、`isAnnotationPresent()`。很多框架会通过反射读取注解，再根据注解信息完成路由、序列化、依赖注入或网络请求配置。

**易错点：** 默认或 `CLASS` 保留策略的注解运行期读不到。方法参数注解通常是二维数组，因为一个方法有多个参数，每个参数又可以有多个注解。

**关联知识点：** [Java 反射 - 注解和泛型反射](../知识点梳理/反射.md#注解和泛型反射)

###### 泛型和反射有什么关系

答案：

**简答：** 泛型主要在编译期生效，运行期普通对象通常拿不到完整泛型实参，但反射可以读取声明处保留的部分泛型信息。

**展开回答：** 例如字段 `List<User> users`，可以通过 `Field.getGenericType()` 拿到声明类型，再判断是否是 `ParameterizedType`，从中解析 `User`。常见类型有 `Type`、`ParameterizedType`、`TypeVariable`、`WildcardType`、`GenericArrayType`。

**易错点：** `Class<?>` 只能表示原始类型，不能完整表示 `List<User>` 里的 `User`。不能直接 `obj instanceof List<String>`。

**关联知识点：** [Java 反射 - 注解和泛型反射](../知识点梳理/反射.md#注解和泛型反射)

###### JDK 动态代理的原理是什么

答案：

**简答：** JDK 动态代理通过 `Proxy.newProxyInstance()` 在运行期创建接口代理对象，并把方法调用转发给 `InvocationHandler`。

**展开回答：** 调用代理对象的方法时，最终会进入 `InvocationHandler.invoke(proxy, method, args)`。框架可以在这里读取 `Method`、注解、参数和返回类型，把一次接口方法调用转换成框架内部逻辑。Retrofit 这类基于接口声明的框架就很适合理解动态代理。

**易错点：** JDK 动态代理只能代理接口，不能直接代理普通类。代理类还要使用合适的类加载器。

**关联知识点：** [Java 反射 - 动态代理和框架能力](../知识点梳理/反射.md#动态代理和框架能力)

###### 反射为什么会影响性能

答案：

**简答：** 反射比直接调用多了查找元信息、访问检查、参数封装、动态分派等成本。

**展开回答：** 直接调用在编译期确定，JIT 更容易优化；反射调用要在运行期解析 `Field` / `Method` / `Constructor`，还可能涉及权限检查、参数装箱拆箱、异常包装。频繁反射尤其容易影响启动和热路径性能。

**易错点：** 反射不是不能用，而是不要在高频路径无缓存地重复查找。常见优化是缓存 `Class`、`Field`、`Method`、`Constructor`，减少启动阶段全量扫描，或改用编译期生成代码。

**关联知识点：** [Java 反射 - Android 使用限制和性能安全](../知识点梳理/反射.md#android-使用限制和性能安全)

###### Android 中使用反射要注意什么

答案：

**简答：** 注意性能、混淆、隐藏 API 限制、系统版本差异和运行期异常。

**展开回答：** Android 中反射常用于框架和兼容层，但业务代码要谨慎。R8/ProGuard 可能改名导致反射找不到类、字段或方法，需要添加 `-keep` 规则。Android 9（API 28）以后对非 SDK 接口有隐藏 API 限制，反射系统隐藏方法可能失败。

**易错点：** 不要把反射隐藏 API 当成稳定能力。不同 Android 版本、厂商 ROM、混淆配置都可能影响结果。

**关联知识点：** [Java 反射 - Android 使用限制和性能安全](../知识点梳理/反射.md#android-使用限制和性能安全)

###### 反射常见异常有哪些

答案：

**简答：** 常见有 `ClassNotFoundException`、`NoSuchMethodException`、`NoSuchFieldException`、`IllegalAccessException`、`InstantiationException`、`InvocationTargetException`。

**展开回答：** `ClassNotFoundException` 表示类名找不到；`NoSuchMethodException` / `NoSuchFieldException` 表示方法或字段签名不匹配；`IllegalAccessException` 表示访问权限不足；`InstantiationException` 常见于接口、抽象类等不能实例化的类型；`InvocationTargetException` 表示目标构造方法或方法内部抛出了异常。

**易错点：** `InvocationTargetException` 只是包装异常，排查时要看 `getCause()` 才能看到真实业务异常。

**关联知识点：** [Java 反射 - 构造方法和对象创建](../知识点梳理/反射.md#构造方法和对象创建)
