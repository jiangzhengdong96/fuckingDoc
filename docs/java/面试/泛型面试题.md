<a id="泛型解决了什么问题"></a>
###### 泛型解决了什么问题

答案：

**简答：** 泛型提升类型安全和代码复用，把类型错误尽量提前到编译期暴露。

**展开回答：** 没有泛型时，集合通常保存 `Object`，取出元素需要手动强制转换，类型错误可能到运行期才出现。泛型让 `List<String>` 只能放入 `String`，取出时也能直接当作 `String` 使用，减少强转和 `ClassCastException`。

**易错点：** 泛型主要是编译期能力，不是运行期万能类型信息。运行期大多数泛型实参会被擦除。

**关联知识点：** [Java 泛型 - 泛型基础](../知识点梳理/泛型.md#泛型基础)

<a id="泛型类和泛型方法有什么区别"></a>
###### 泛型类和泛型方法有什么区别

答案：

**简答：** 泛型类的类型参数作用于整个类，泛型方法的类型参数只作用于当前方法。

**展开回答：** 泛型类在类名后声明类型参数，例如 `class Box<T>`，字段和方法都可以使用 `T`。泛型方法在返回值前声明类型参数，例如 `<T> T first(List<T> list)`，即使所在类不是泛型类，也可以定义泛型方法。

**易错点：** 泛型方法的 `<T>` 要写在返回值前面。方法自己的 `T` 可以和类上的 `T` 无关，但为了可读性不要随意重名造成误解。

**关联知识点：** [Java 泛型 - 泛型类和泛型方法](../知识点梳理/泛型.md#泛型类和泛型方法)

<a id="泛型类上的-t-能不能直接用于静态方法"></a>
###### 泛型类上的 T 能不能直接用于静态方法

答案：

**简答：** 不能直接使用。类上的 `T` 属于具体泛型实例，静态方法属于类本身，两者生命周期和归属不一样。

**展开回答：** 如果静态方法需要泛型，应该在方法返回值前声明自己的类型参数，例如 `public static <K> K identity(K value)`。方法自己的 `<K>` 和类上的 `<T>` 是两套类型参数。

**易错点：** 泛型方法可以声明和类同名的 `<T>`，但这会遮蔽类上的 `T`，可读性差，建议避免。

**关联知识点：** [Java 泛型 - 泛型类和泛型方法](../知识点梳理/泛型.md#泛型类和泛型方法)

<a id="什么是类型擦除"></a>
###### 什么是类型擦除

答案：

**简答：** Java 泛型主要在编译期生效，编译后类型参数会被擦除为边界类型，没有边界时通常擦除为 `Object`。

**展开回答：** 编译器会根据泛型做类型检查，在必要位置插入强制类型转换，并可能生成桥接方法来保持多态。运行期通常看不到 `List<String>` 和 `List<Integer>` 的完整差异，它们的 `getClass()` 通常是同一个 `ArrayList.class`。

**易错点：** 类型擦除不代表所有泛型信息都完全消失。字段、方法返回值、父类签名等声明处的泛型信息可能通过反射 `Type` API 读取。

**关联知识点：** [Java 泛型 - 类型擦除](../知识点梳理/泛型.md#类型擦除)

<a id="listobject-和-liststring-是什么关系"></a>
###### ListObject 和 ListString 是什么关系

答案：

**简答：** `List<String>` 不是 `List<Object>` 的子类，二者没有泛型继承关系。

**展开回答：** 即使 `String` 是 `Object` 的子类，`List<String>` 和 `List<Object>` 也不是父子关系。否则如果允许把 `List<String>` 赋值给 `List<Object>`，就可以往里面放 `Integer`，再按 `String` 取出时就会出错。

**易错点：** 可以把 `ArrayList<String>` 向上转型为 `List<String>`，因为这是实现类到接口的继承关系；不能把 `ArrayList<String>` 转成 `ArrayList<Object>` 或 `List<Object>`。

**关联知识点：** [Java 泛型 - 类型参数和边界](../知识点梳理/泛型.md#类型参数和边界)

<a id="extends-和-super-通配符怎么选"></a>
###### extends 和 super 通配符怎么选

答案：

**简答：** 读取为主用 `? extends T`，写入为主用 `? super T`，也就是 PECS：Producer Extends, Consumer Super。

**展开回答：** `List<? extends Number>` 可以接收 `List<Integer>`、`List<Double>` 等，适合把元素当作 `Number` 读取，但不能安全写入具体 `Integer` 或 `Double`。`List<? super Integer>` 可以接收 `List<Integer>`、`List<Number>`、`List<Object>`，适合写入 `Integer`，但读取出来通常只能当作 `Object`。

**易错点：** `extends` 不是“只能读绝对不能写”，它可以写 `null`，但不能安全写入具体子类型；`super` 不是“不能读”，而是读取类型会变宽，通常只能按 `Object` 使用。

**关联知识点：** [Java 泛型 - 通配符](../知识点梳理/泛型.md#通配符)

<a id="为什么不能直接-new-t"></a>
###### 为什么不能直接 new T

答案：

**简答：** 因为类型擦除后运行期不知道 `T` 的具体类型和构造方法。

**展开回答：** `new T()` 需要在运行期知道要创建哪个类，但 Java 泛型擦除后普通类型参数没有完整运行期类型信息。如果需要创建泛型对象，通常传入 `Class<T>`、工厂方法或 `Supplier<T>`。

```java
public static <T> T create(Supplier<T> supplier) {
    return supplier.get();
}
```

**易错点：** 通过 `Class<T>` 反射创建对象时，也要处理无参构造、访问权限和异常问题，不是所有类型都能安全创建。

**关联知识点：** [Java 泛型 - 泛型限制](../知识点梳理/泛型.md#泛型限制)

<a id="为什么不能使用-listint"></a>
###### 为什么不能使用 Listint

答案：

**简答：** Java 泛型类型参数必须是引用类型，不能直接使用基本类型，所以不能写 `List<int>`，要写 `List<Integer>`。

**展开回答：** Java 泛型通过类型擦除实现，没有边界时类型参数会按引用类型处理，基本类型不能作为泛型实参。实际开发中依赖自动装箱和拆箱，把 `int` 包装成 `Integer`。

**易错点：** `List<Integer>` 会有装箱开销。在性能敏感场景，可以考虑基本类型数组、专用集合或其他更合适的数据结构。

**关联知识点：** [Java 泛型 - 泛型限制](../知识点梳理/泛型.md#泛型限制)

<a id="为什么不能创建泛型数组"></a>
###### 为什么不能创建泛型数组

答案：

**简答：** 因为数组运行期保留元素类型，泛型运行期类型擦除，二者机制冲突，容易造成堆污染。

**展开回答：** 数组是协变且运行期检查元素类型的，例如 `String[]` 运行期知道自己只能放 `String`。泛型的 `List<String>` 运行期通常只知道是 `List`，不知道元素一定是 `String`。如果允许直接创建 `new List<String>[10]`，就可能通过数组协变写入不安全的泛型元素。

**易错点：** 可以声明 `List<String>[] lists`，但不能直接 `new List<String>[10]`。如果确实需要数组，可以用 `Array.newInstance()` 创建原始数组后做受控强转，或者优先改用 `List<T>`。

**关联知识点：** [Java 泛型 - 泛型和数组](../知识点梳理/泛型.md#泛型和数组)

<a id="泛型和反射有什么关系"></a>
###### 泛型和反射有什么关系

答案：

**简答：** 泛型运行期大多被擦除，但声明处保留的部分泛型信息可以通过反射 `Type` API 读取。

**展开回答：** `Class<T>`、`Constructor<T>` 等反射 API 本身也使用泛型，能减少强转。字段、方法返回值、父类签名上的泛型信息可以通过 `getGenericType()`、`getGenericReturnType()`、`getGenericSuperclass()` 等 API 读取。如果要解析 `List<User>` 里的 `User`，通常要处理 `ParameterizedType`。类似 `class UserRepo extends BaseRepo<User>` 这种写死在继承签名里的类型，也可以通过父类泛型声明解析出来。

**易错点：** `Class<List>` 只能表达原始 `List` 类型，不能表达 `List<User>`。JSON 解析复杂泛型时通常需要 `TypeToken` / `TypeReference` 或等价能力。

**关联知识点：** [Java 泛型 - 泛型和反射](../知识点梳理/泛型.md#泛型和反射)

<a id="list-能读写什么"></a>
###### List<?> 能读写什么

答案：

**简答：** `List<?>` 可以接收任意具体泛型列表，读取出来只能安全当作 `Object`，不能添加具体元素，除了 `null`。

**展开回答：** `List<?>` 的意思是“某种未知元素类型的 List”。它可以指向 `List<String>`、`List<Integer>` 等，但编译器不知道真实元素类型，所以不能往里面添加 `String` 或 `Integer`。读取时也只能按所有引用类型的共同父类 `Object` 使用。

**易错点：** `List<?>` 不是 raw type。它仍然保留泛型检查，只是元素类型未知；`List list` 才是绕过泛型检查的原始类型。

**关联知识点：** [Java 泛型 - 通配符](../知识点梳理/泛型.md#通配符)

<a id="什么是-raw-type-和-unchecked-warning"></a>
###### 什么是 raw type 和 unchecked warning

答案：

**简答：** raw type 是不带泛型参数的原始类型，例如 `List list`；unchecked warning 表示编译器无法完全验证类型安全。

**展开回答：** 使用 raw type 会绕过泛型检查，例如可以把 `Integer` 放进原本期望 `String` 的列表，问题可能到读取时才暴露。unchecked warning 常见于泛型强转、反射创建泛型数组、旧 API 兼容等场景。

**易错点：** 不要用 `@SuppressWarnings("unchecked")` 粗暴压掉大范围警告。应该尽量缩小作用范围，并确认强转逻辑受控。

**关联知识点：** [Java 泛型 - 泛型限制](../知识点梳理/泛型.md#泛型限制)

<a id="泛型在-android-中有哪些常见场景"></a>
###### 泛型在 Android 中有哪些常见场景

答案：

**简答：** 常见于集合、Adapter、Repository、网络响应包装、回调、状态容器、JSON 解析和数据库框架。

**展开回答：** 例如 `BaseResponse<User>`、`List<User>`、`Result<T>`、`Callback<T>`、`Repository<T>` 都依赖泛型提升复用性和类型安全。Retrofit、Moshi、Gson、Room 等框架会读取泛型返回值或字段类型，复杂泛型通常要结合反射和 `Type` 信息处理。

**易错点：** JSON 解析时只传 `List.class` 通常不够，因为它不知道元素类型是 `User`。复杂泛型解析要传完整 `Type`，例如 `TypeToken<List<User>>` 这类结构。

**关联知识点：** [Java 泛型 - Android 使用场景和注意点](../知识点梳理/泛型.md#android-使用场景和注意点)
