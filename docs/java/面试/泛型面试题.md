## 泛型解决了什么问题

**简答：** 泛型提升类型安全和代码复用。

**展开回答：** 泛型让类型约束前移到编译期，减少强制类型转换和运行期类型错误。

**易错点：** 泛型不是运行期万能类型信息。

**关联知识点：** [Java 泛型](../知识点梳理/泛型.md)

## 什么是类型擦除

**简答：** Java 泛型主要在编译期生效，编译后泛型类型信息会被擦除。

**展开回答：** 编译器会做类型检查和必要的类型转换，运行期通常看不到完整泛型参数。

**易错点：** 不能直接 `obj instanceof List<String>`。

**关联知识点：** [Java 泛型](../知识点梳理/泛型.md)

## ListObject 和 ListString 是什么关系

**简答：** `List<String>` 不是 `List<Object>` 的子类。

**展开回答：** 即使 `String` 是 `Object` 的子类，`List<String>` 和 `List<Object>` 也不是父子关系。

**易错点：** 泛型类型默认不协变。

**关联知识点：** [Java 泛型](../知识点梳理/泛型.md)

## extends 和 super 通配符怎么选

**简答：** 读取为主用 `? extends T`，写入为主用 `? super T`。

**展开回答：** 常用规则是 PECS：Producer Extends, Consumer Super。

**易错点：** `extends` 限制写入，`super` 读取时类型会变宽。

**关联知识点：** [Java 泛型](../知识点梳理/泛型.md)

## 为什么不能直接 new T

**简答：** 因为类型擦除后运行期不知道 T 的具体类型。

**展开回答：** 如果需要创建泛型对象，通常传入 `Class<T>`、工厂方法或 Supplier。

**易错点：** 泛型数组也有类似限制。

**关联知识点：** [Java 泛型](../知识点梳理/泛型.md)
