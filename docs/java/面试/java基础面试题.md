<a id="java-为什么大小写敏感"></a>
###### Java 为什么大小写敏感

答案：

**简答：** Java 区分大小写，`Hello` 和 `hello` 是两个不同标识符。

**展开回答：** Java 的类名、变量名、方法名都属于标识符，编译器会按字符精确识别。大小写不同会被视为不同名字。

**易错点：** `public` 类名和源文件名也要大小写一致。

**关联知识点：** [Java 基础 - 基础语法](../知识点梳理/java基础.md#基础语法)

<a id="java-标识符和命名规范有哪些注意点"></a>
###### Java 标识符和命名规范有哪些注意点

答案：

**简答：** 标识符可由字母、数字、`_`、`$` 等组成，但不能以数字开头，也不能使用关键字。

**展开回答：** 类名通常大驼峰，方法名和变量名通常小驼峰，常量通常全大写并用下划线分隔。实际编码里不建议随意使用 `$`，它常见于编译器生成类名或内部类相关命名。

**易错点：** 能编译不等于符合项目规范，命名更多是可读性和团队约定问题。

**关联知识点：** [Java 基础 - 基础语法](../知识点梳理/java基础.md#基础语法)

<a id="访问修饰符-public-protected-default-private-有什么区别"></a>
###### 访问修饰符 public protected default private 有什么区别

答案：

**简答：** `public` 任意位置可访问；`protected` 同包和子类可访问；默认访问权限同包可访问；`private` 仅本类可访问。

**展开回答：** `protected` 比较容易混淆，它不等于任意地方拿到子类对象都能访问父类 protected 成员，跨包子类访问时通常要通过当前子类对象或子类引用访问继承来的成员。

**易错点：** 顶层类不能用 `private` 或 `protected` 修饰。

**关联知识点：** [Java 基础 - 修饰符](../知识点梳理/java基础.md#修饰符)

<a id="static-修饰变量方法代码块分别表示什么"></a>
###### static 修饰变量方法代码块分别表示什么

答案：

**简答：** `static` 表示属于类，而不是属于某个对象。

**展开回答：** static 变量多个对象共享一份；static 方法可以通过类名调用，不能直接访问非静态成员；static 代码块在类初始化时执行一次，常用于初始化静态资源。

**易错点：** static 成员生命周期较长，静态变量长期持有大对象或 Context 容易造成内存问题。

**关联知识点：** [Java 基础 - 修饰符](../知识点梳理/java基础.md#修饰符)

<a id="static-final-一定是编译期常量吗"></a>
###### static final 一定是编译期常量吗

答案：

**简答：** 不一定。

**展开回答：** 只有 `基本类型/String + final + static + 编译期可确定的初始化值`，通常才属于编译期常量。比如 `static final int A = 1` 是典型编译期常量；如果值来自方法调用或对象创建，就不是编译期常量。

**易错点：** `static final` 只是修饰符组合，不自动等于“会被编译器内联的常量”。

**关联知识点：** [Java 基础 - 修饰符](../知识点梳理/java基础.md#修饰符)

<a id="final-可以修饰什么"></a>
###### final 可以修饰什么

答案：

**简答：** `final` 可以修饰类、方法、变量。

**展开回答：** final 类不能被继承；final 方法不能被重写；final 变量赋值后不能重新赋值。修饰基本类型表示值不能变；修饰引用类型表示引用不能再指向其他对象，但对象内部状态是否能变取决于对象本身。

**易错点：** `final List list` 不能重新赋值，但如果 List 本身可变，仍然可以添加或删除元素。

**关联知识点：** [Java 基础 - 修饰符](../知识点梳理/java基础.md#修饰符)

<a id="抽象方法为什么不能同时用-final-或-static-修饰"></a>
###### 抽象方法为什么不能同时用 final 或 static 修饰

答案：

**简答：** 因为语义冲突。

**展开回答：** 抽象方法要求子类去实现；`final` 表示不能被重写，两者冲突。`static` 方法属于类，不参与普通实例方法的动态分派，也不能作为需要子类实现的抽象实例行为。

**易错点：** 抽象类可以没有抽象方法，但有抽象方法的类必须声明为抽象类。

**关联知识点：** [Java 基础 - 修饰符](../知识点梳理/java基础.md#修饰符)

<a id="局部变量成员变量静态变量有什么区别"></a>
###### 局部变量成员变量静态变量有什么区别

答案：

**简答：** 局部变量定义在方法或代码块中；成员变量定义在类中、方法体外，属于对象；静态变量属于类。

**展开回答：** 局部变量随方法调用进入栈帧，方法结束后销毁；成员变量随对象创建存在；静态变量通常随类加载创建，类卸载时销毁。成员变量和静态变量有默认值，局部变量没有默认值。

**易错点：** 访问修饰符不能修饰局部变量，`static` 也不能修饰局部变量。

**关联知识点：** [Java 基础 - 变量](../知识点梳理/java基础.md#变量)

<a id="局部变量为什么必须初始化"></a>
###### 局部变量为什么必须初始化

答案：

**简答：** 因为局部变量没有默认值，使用前必须明确赋值。

**展开回答：** 局部变量存在于方法调用的局部作用域中，编译器要求在所有可能执行路径上使用前已经初始化，避免读取不确定值。

**易错点：** 成员变量有默认值，不代表局部变量也有默认值。

**关联知识点：** [Java 基础 - 变量](../知识点梳理/java基础.md#变量)

<a id="一个-java-源文件可以有多个-public-类吗"></a>
###### 一个 Java 源文件可以有多个 public 类吗

答案：

**简答：** 不能，一个 `.java` 源文件最多只能有一个 `public` 顶层类。

**展开回答：** 源文件名必须和 `public` 类名一致；一个源文件可以有多个非 public 顶层类。

**易错点：** 没有 `public` 类时，源文件名不必和某个类名完全一致，但实际项目通常仍按主类名组织文件。

**关联知识点：** [Java 基础 - 源文件声明规则](../知识点梳理/java基础.md#源文件声明规则)

<a id="java-有哪些数据类型"></a>
###### Java 有哪些数据类型

答案：

**简答：** Java 数据类型分为基本数据类型和引用数据类型。

**展开回答：** 基本数据类型包括 `byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`。引用数据类型包括字符串、数组、自定义类和 Java 自带类等。

**易错点：** `String` 不是基本数据类型；数组也是对象。

**关联知识点：** [Java 基础 - Java 的两大数据类型](../知识点梳理/java基础.md#java-的两大数据类型)

<a id="char-为什么不一定表示一个完整字符"></a>
###### char 为什么不一定表示一个完整字符

答案：

**简答：** 因为 Java 的 `char` 是 16 位 Unicode 代码单元，不一定能表示所有 Unicode 字符。

**展开回答：** 一些 emoji 或生僻字可能需要两个 `char` 组成代理对才能表示完整字符，所以 `char` 不等于“一个用户看到的完整字符”。

**易错点：** 字符串长度、字符个数、Unicode 码点数量不是一回事。

**关联知识点：** [Java 基础 - Java 的两大数据类型](../知识点梳理/java基础.md#java-的两大数据类型)

<a id="byte-short-char-参与运算时会发生什么"></a>
###### byte short char 参与运算时会发生什么

答案：

**简答：** 通常会先提升为 `int` 再参与运算。

**展开回答：** `byte`、`short`、`char` 做算术运算时结果通常是 `int`，因此赋值回较小类型时可能需要强制类型转换。

**易错点：** `byte b = 1; b = b + 1;` 不能直接编译通过，因为 `b + 1` 的结果是 `int`。

**关联知识点：** [Java 基础 - Java 的两大数据类型](../知识点梳理/java基础.md#java-的两大数据类型)

<a id="自动类型转换和强制类型转换有什么区别"></a>
###### 自动类型转换和强制类型转换有什么区别

答案：

**简答：** 自动类型转换通常是小范围到大范围；强制类型转换通常是大范围到小范围。

**展开回答：** 自动转换不需要显式写转换符；强制转换需要显式写目标类型，可能丢失精度或溢出。浮点数转整数会直接截断小数部分，不是四舍五入。

**易错点：** `long` 到 `float` 可能是自动转换，但可能有精度损失，因为 float 表示范围大但有效精度有限。

**关联知识点：** [Java 基础 - Java 的两大数据类型](../知识点梳理/java基础.md#java-的两大数据类型)

<a id="为什么金额计算不推荐用-float-或-double"></a>
###### 为什么金额计算不推荐用 float 或 double

答案：

**简答：** 因为 `float` 和 `double` 是二进制浮点数，很多十进制小数不能精确表示。

**展开回答：** 金额计算要求精确，浮点数可能出现精度误差。Java 中通常使用 `BigDecimal`，并优先用字符串构造，比如 `new BigDecimal("0.1")`。

**易错点：** `new BigDecimal(0.1)` 仍然会带入 double 的精度问题。

**关联知识点：** [Java 基础 - Java 的两大数据类型](../知识点梳理/java基础.md#java-的两大数据类型)

<a id="短路逻辑运算符和普通逻辑运算符有什么区别"></a>
###### 短路逻辑运算符和普通逻辑运算符有什么区别

答案：

**简答：** `&&`、`||` 有短路；`&`、`|` 用在 boolean 表达式时不短路。

**展开回答：** `&&` 左侧为 false 时右侧不再执行；`||` 左侧为 true 时右侧不再执行。`&`、`|` 两边都会执行，同时它们也可以作为整数位运算符。

**易错点：** 如果右侧表达式有方法调用或副作用，短路与否会影响执行结果。

**关联知识点：** [Java 基础 - 运算符](../知识点梳理/java基础.md#运算符)

<a id="instanceof-的作用是什么"></a>
###### instanceof 的作用是什么

答案：

**简答：** `instanceof` 用于判断对象是否是某个类或接口类型的实例。

**展开回答：** 它返回 boolean，可以判断类类型，也可以判断接口类型。判断前左侧必须是引用类型表达式，不能直接用于基本类型。

**易错点：** `null instanceof Xxx` 结果是 false。

<a id="自动装箱和自动拆箱是什么"></a>
###### 自动装箱和自动拆箱是什么

答案：

**简答：** 自动装箱是基本类型自动转包装类；自动拆箱是包装类自动转基本类型。

**展开回答：** 例如 `Integer i = 1` 会触发装箱，`int x = i` 会触发拆箱。编译器会在合适位置插入 `valueOf()` 或 `xxxValue()` 调用。

**易错点：** 包装类为 `null` 时自动拆箱会抛 `NullPointerException`。

**关联知识点：** [Java 基础 - 包装器类](../知识点梳理/java基础.md#包装器类)

<a id="integer-127-和-128-用等号比较有什么区别"></a>
###### Integer 127 和 128 用等号比较有什么区别

答案：

**简答：** `Integer` 自动装箱后，`127` 默认通常命中缓存，`128` 默认通常不命中缓存。

**展开回答：** `Integer.valueOf()` 默认缓存 `-128 ~ 127` 范围内的对象，所以两个 `Integer` 变量装箱为 `127` 时，`==` 可能为 true；`128` 通常会创建不同对象，`==` 可能为 false。

**易错点：** 包装类对象比较值应该用 `equals()`，不要依赖 `==`。

**关联知识点：** [Java 基础 - 包装器类](../知识点梳理/java基础.md#包装器类)

<a id="包装类缓存和常量池是一回事吗"></a>
###### 包装类缓存和常量池是一回事吗

答案：

**简答：** 不是。

**展开回答：** 包装类缓存是包装类自身维护的一批复用对象，例如 `IntegerCache`；字符串常量池是 JVM 对 `String` 的共享机制；`.class` 常量池和运行时常量池又是另外的概念。

**易错点：** `Integer a = 127; Integer b = 127; a == b` 为 true 不是因为整数在字符串常量池里，而是因为包装类缓存。

**关联知识点：** [Java 基础 - 包装器类](../知识点梳理/java基础.md#包装器类)

<a id="数组是不是对象-length-是字段还是方法"></a>
###### 数组是不是对象 length 是字段还是方法

答案：

**简答：** 数组是对象，`length` 是字段，不是方法。

**展开回答：** 数组创建后长度固定，元素有默认值。数字类型默认 `0`，boolean 默认 `false`，引用类型默认 `null`。

**易错点：** 数组是 `arr.length`，字符串是 `str.length()`。

**关联知识点：** [Java 基础 - 数组](../知识点梳理/java基础.md#数组)

<a id="java-数组协变有什么问题"></a>
###### Java 数组协变有什么问题

答案：

**简答：** 数组协变允许 `Object[] arr = new String[1]` 编译通过，但运行时放入非 String 会抛异常。

**展开回答：** 数组运行期仍知道真实元素类型，所以当向 `String[]` 真实数组里放入非 String 对象时，会抛 `ArrayStoreException`。

**易错点：** 泛型集合通常不支持这种协变，比如 `List<String>` 不是 `List<Object>` 的子类。

**关联知识点：** [Java 基础 - 数组](../知识点梳理/java基础.md#数组)

<a id="静态代码块构造代码块普通代码块同步代码块有什么区别"></a>
###### 静态代码块构造代码块普通代码块同步代码块有什么区别

答案：

**简答：** 它们的执行时机和用途不同。

**展开回答：** 静态代码块在类初始化时执行一次；构造代码块在每次创建对象时、构造方法前执行；普通代码块在方法执行到该位置时执行；同步代码块用于线程同步，需要指定锁对象。

**易错点：** 静态代码块不能直接访问非静态成员。

**关联知识点：** [Java 基础 - 代码块](../知识点梳理/java基础.md)

<a id="可变参数的本质是什么"></a>
###### 可变参数的本质是什么

答案：

**简答：** 可变参数本质上是数组。

**展开回答：** `type... args` 在方法内部可以像数组一样使用；一个方法最多只能有一个可变参数，并且必须放在参数列表最后。

**易错点：** 可变参数和数组参数可能导致重载匹配不直观，设计 API 时要谨慎。

**关联知识点：** [Java 基础 - 可变参数](../知识点梳理/java基础.md#可变参数)

<a id="main-方法为什么是固定签名"></a>
###### main 方法为什么是固定签名

答案：

**简答：** JVM 启动 Java 程序时会按约定查找 `public static void main(String[] args)`。

**展开回答：** `public` 保证 JVM 可访问；`static` 表示不需要创建对象即可调用；`void` 表示没有返回值；`String[] args` 接收命令行参数。

**易错点：** `main` 方法可以重载，但程序入口只认标准签名。

**关联知识点：** [Java 基础 - 主方法](../知识点梳理/java基础.md)

<a id="递归需要注意什么"></a>
###### 递归需要注意什么

答案：

**简答：** 递归要有终止条件，并且每次调用都要逼近终止条件。

**展开回答：** 每次递归调用都会创建新的栈帧，递归过深可能抛 `StackOverflowError`。Java 一般不做尾递归优化，深递归场景常要改写成循环、显式栈或加记忆化。

**易错点：** 不要指望编译器自动消除深递归带来的栈风险。

**关联知识点：** [Java 基础 - 递归](../知识点梳理/java基础.md#递归)

<a id="java-程序员能不能手动释放对象"></a>
###### Java 程序员能不能手动释放对象

答案：

**简答：** 不能像 C/C++ 那样直接释放对象内存，只能让对象变成不可达，等待 GC 回收。

**展开回答：** Java 对象内存由垃圾回收器管理。开发者可以断开引用，比如把不再需要的引用置为 `null`，但不能保证对象马上被回收。

**易错点：** 文件、Socket、数据库连接等资源不是普通堆对象内存，不能等 GC，应该主动关闭。

**关联知识点：** [Java 基础 - 垃圾回收](../知识点梳理/java基础.md#垃圾回收)

<a id="jvm-怎么判断对象是否可以回收"></a>
###### JVM 怎么判断对象是否可以回收

答案：

**简答：** 主流 JVM 通常使用可达性分析。

**展开回答：** 从 GC Roots 出发，如果一个对象不可达，就可能被回收。常见 GC Roots 包括虚拟机栈中的引用、静态属性引用、常量引用、本地方法栈 JNI 引用等。

**易错点：** 不能简单说 JVM 只靠引用计数判断对象是否可回收。

**关联知识点：** [Java 基础 - 垃圾回收](../知识点梳理/java基础.md#垃圾回收)

<a id="systemgc-一定会马上触发-gc-吗"></a>
###### System.gc 一定会马上触发 GC 吗

答案：

**简答：** 不一定。

**展开回答：** `System.gc()` 只是建议 JVM 执行 GC，JVM 可以选择执行，也可以不马上执行。实际是否触发以及何时触发取决于 JVM 实现和运行状态。

**易错点：** 不要把 `System.gc()` 当作确定性的资源释放机制。

**关联知识点：** [Java 基础 - 垃圾回收](../知识点梳理/java基础.md#垃圾回收)

<a id="为什么不应该依赖-finalize-释放资源"></a>
###### 为什么不应该依赖 finalize 释放资源

答案：

**简答：** `finalize()` 已经过时，不可靠，也不保证及时执行。

**展开回答：** 资源释放应该使用明确的关闭逻辑，例如 `close()`、`try-with-resources`。`finalize()` 执行时机不可控，还可能带来性能和对象复活等问题。

**易错点：** IO、Socket、数据库连接这类资源必须主动释放。

**关联知识点：** [Java 基础 - 垃圾回收](../知识点梳理/java基础.md#垃圾回收)

<a id="深拷贝和浅拷贝有什么区别"></a>
###### 深拷贝和浅拷贝有什么区别

答案：

**简答：** 浅拷贝复制基本类型值和引用地址；深拷贝会递归复制引用对象本身。

**展开回答：** 浅拷贝后，新旧对象内部的引用字段可能指向同一个子对象；深拷贝会为子对象也创建独立副本，修改一方不影响另一方。

**易错点：** 深拷贝不只是复制第一层对象，关键看引用字段是否也被独立复制。

**关联知识点：** [Java 基础 - 深拷贝和浅拷贝](../知识点梳理/java基础.md#深拷贝和浅拷贝)

<a id="java-是值传递还是引用传递"></a>
###### Java 是值传递还是引用传递

答案：

**简答：** Java 只有值传递。

**展开回答：** 基本类型传递的是值的拷贝；对象作为参数时，传递的是对象引用的拷贝。方法内部可以通过这份引用拷贝修改对象状态，但不能改变调用方变量保存的引用地址。

**易错点：** “对象内容能被修改”不等于“Java 是引用传递”。

**关联知识点：** [Java 基础 - 值传递和引用传递](../知识点梳理/java基础.md#值传递和引用传递)
