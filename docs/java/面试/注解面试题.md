###### 什么是注解注解解决了什么问题

答案：

**简答：** 注解是代码里的元数据，用来描述类、方法、字段、参数等元素的信息。

**展开回答：** 注解本身不会自动改变代码行为，真正产生效果的是编译器、注解处理器、框架或运行期反射逻辑。注解类型本身也是一种特殊接口类型，运行期读取注解时拿到的是实现 `Annotation` 语义的注解对象。它可以用于编译期检查、生成代码、运行期读取配置、约束 API 使用方式等。

**易错点：** 注解不是业务逻辑本身。注解适合描述稳定元数据，不适合承载复杂业务流程。

**关联知识点：** [Java 注解 - 注解基础](../知识点梳理/注解.md#注解基础)

###### 注解的参数可以有哪些类型

答案：

**简答：** 注解参数只能使用基本类型、`String`、`Class`、枚举、注解，以及这些类型的数组。

**展开回答：** 注解参数本质上是无参数方法，可以通过 `default` 声明默认值。如果只有一个参数并且参数名是 `value`，使用注解时可以省略参数名。

```java
public @interface Api {
    String value();
    boolean cache() default false;
}

@Api("/user/list")
public void listUser() {
}
```

**易错点：** 注解参数不能直接使用普通对象类型，参数值也必须是编译期常量，不能使用运行期变量。

**关联知识点：** [Java 注解 - 注解参数](../知识点梳理/注解.md#注解参数)

###### Target 和 Retention 分别有什么作用

答案：

**简答：** `@Target` 决定注解能用在哪里，`@Retention` 决定注解保留到哪个阶段。

**展开回答：** `@Target(ElementType.METHOD)` 表示注解只能用于方法；`@Retention(RetentionPolicy.RUNTIME)` 表示注解保留到运行期，可以通过反射读取。自定义注解通常建议明确写出这两个元注解，避免误用或运行期读不到。

**易错点：** 不写 `@Retention` 时默认是 `CLASS`，运行期反射通常读不到；不写 `@Target` 时注解可用于很多位置，容易造成语义混乱。

**关联知识点：** [Java 注解 - 元注解](../知识点梳理/注解.md#元注解)

###### RetentionPolicy SOURCE CLASS RUNTIME 有什么区别

答案：

**简答：** `SOURCE` 只保留在源码，`CLASS` 保留到 class 文件，`RUNTIME` 保留到运行期并可被反射读取。

**展开回答：** `SOURCE` 常用于编译器检查或 Lint 检查；`CLASS` 常用于编译期或字节码处理；`RUNTIME` 常用于运行时框架通过反射读取注解。是否选择 `RUNTIME` 取决于运行期是否真的需要读取，不应该无脑设置。

**易错点：** 编译期注解处理不一定需要 `RUNTIME`。很多生成代码或静态检查场景用 `SOURCE` / `CLASS` 更合适。

**关联知识点：** [Java 注解 - 元注解](../知识点梳理/注解.md#元注解)

###### Inherited 有什么限制

答案：

**简答：** `@Inherited` 只对类上的注解继承有效，并且只作用于 class 的继承关系。

**展开回答：** 如果父类上有一个带 `@Inherited` 的注解，子类在没有直接声明该注解时，可以通过反射看到继承来的注解。但它不作用于接口继承，也不作用于方法、字段、参数等位置。

**易错点：** 不要以为 `@Inherited` 会让接口、方法或字段上的注解自动继承。

**关联知识点：** [Java 注解 - 元注解](../知识点梳理/注解.md#元注解)

###### Repeatable 是什么

答案：

**简答：** `@Repeatable` 表示同一个注解可以在同一位置重复使用。

**展开回答：** 使用 `@Repeatable` 时需要定义一个容器注解，用来承载多个重复注解。它适合一个元素需要声明多个同类规则的场景，例如多个路由、多个校验规则等。

**易错点：** `@Repeatable` 不是简单加上就结束，还需要容器注解配合，并且保留策略和作用目标要设计一致。

**关联知识点：** [Java 注解 - 元注解](../知识点梳理/注解.md#元注解)

###### 运行时注解怎么读取

答案：

**简答：** 运行时注解通过反射读取，前提是注解使用 `@Retention(RetentionPolicy.RUNTIME)`。

**展开回答：** 常见 API 有 `isAnnotationPresent()`、`getAnnotation()`、`getDeclaredAnnotation()`、`getAnnotations()`、`getDeclaredAnnotations()`。类、字段、方法、构造方法都可以读取注解；方法参数注解通常通过 `getParameterAnnotations()` 获取二维数组。

```java
Route route = HomeActivity.class.getAnnotation(Route.class);
boolean hasRoute = HomeActivity.class.isAnnotationPresent(Route.class);
```

**易错点：** 如果注解不是 `RUNTIME` 保留策略，运行期反射通常读不到。

**关联知识点：** [Java 注解 - 运行时注解和反射读取](../知识点梳理/注解.md#运行时注解和反射读取)

###### getAnnotation 和 getDeclaredAnnotation 有什么区别

答案：

**简答：** `getAnnotation()` 获取可见注解，类上的 `@Inherited` 可能影响结果；`getDeclaredAnnotation()` 只获取当前元素直接声明的注解。

**展开回答：** 对类来说，如果父类上的注解带有 `@Inherited`，子类调用 `getAnnotation()` 可能拿到继承来的注解；`getDeclaredAnnotation()` 只看子类自己是否直接声明。字段、方法等位置不受 `@Inherited` 继承影响。

**易错点：** 如果你要判断“当前类自己有没有声明某注解”，应使用 `getDeclaredAnnotation()` 或 `getDeclaredAnnotations()`。

**关联知识点：** [Java 注解 - 运行时注解和反射读取](../知识点梳理/注解.md#运行时注解和反射读取)

###### 运行时注解和编译期注解处理有什么区别

答案：

**简答：** 运行时注解是在程序运行时通过反射读取；编译期注解处理是在编译阶段扫描注解并生成代码或做检查。

**展开回答：** 运行时注解灵活，但有反射成本和混淆风险；编译期注解处理能把很多工作前移到编译期，减少运行时扫描，提高启动性能，也能更早暴露错误。Room、Hilt、Dagger、Glide 等 Android 框架大量使用编译期处理或生成代码。

**易错点：** 运行时注解不等于注解处理器；注解处理器也不一定要求注解保留到 `RUNTIME`。

**关联知识点：** [Java 注解 - 编译期注解处理](../知识点梳理/注解.md#编译期注解处理)

###### APT KAPT KSP 大概是什么

答案：

**简答：** 它们都是编译期处理注解或符号信息并生成代码的工具链，只是面向 Java/Kotlin 的方式不同。

**展开回答：** APT 是 Java 标准注解处理机制；KAPT 是 Kotlin 使用 Java 注解处理器的兼容方案；KSP 是 Kotlin Symbol Processing，更贴近 Kotlin 符号模型，通常比 KAPT 更适合 Kotlin 项目。Android 项目里 Room、Hilt、Dagger、Glide 等都可能涉及这些工具链。

**易错点：** APT/KAPT/KSP 通常生成新代码或中间文件，不是直接修改你已有的源码文件。

**关联知识点：** [Java 注解 - 编译期注解处理](../知识点梳理/注解.md#编译期注解处理)

###### Android 中使用注解要注意什么

答案：

**简答：** 注意处理阶段、性能、混淆、生成代码和框架规则。

**展开回答：** Retrofit 更偏运行期读取接口方法注解；Room、Hilt、Dagger、Glide 更偏编译期生成代码；Lint 和 AndroidX 注解更偏静态检查。运行时反射读取注解时，要注意 R8/ProGuard 混淆规则；编译期生成代码时，要注意 Gradle 插件、KAPT/KSP 配置和增量编译影响。

**易错点：** 不能看到注解就认为都是运行时反射。不同框架处理注解的阶段不一样。

**关联知识点：** [Java 注解 - Android 使用场景和注意点](../知识点梳理/注解.md#android-使用场景和注意点)

###### 自定义注解时要注意什么

答案：

**简答：** 明确注解用途、`@Target`、`@Retention`、参数类型、默认值和处理方式。

**展开回答：** 如果注解只用于静态检查或编译期生成代码，不一定需要 `RUNTIME`；如果要运行时反射读取，就必须设置 `RUNTIME`。注解参数尽量简单稳定，不要把复杂业务配置都塞进注解。

**易错点：** 不写 `@Retention` 默认是 `CLASS`，这会导致运行期反射读不到；不写 `@Target` 会让注解能用在过多位置，降低语义清晰度。

**关联知识点：** [Java 注解 - 注解基础](../知识点梳理/注解.md#注解基础)
