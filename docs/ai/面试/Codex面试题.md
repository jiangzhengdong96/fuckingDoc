<a id="codex-和普通-chatbot-有什么区别"></a>
###### Codex 和普通 Chatbot 有什么区别

答案：

**简答：** Codex 面向代码仓库协作，可以读取项目上下文、修改文件、运行命令和根据检查结果继续修正；普通 Chatbot 更偏对话和概念回答。

**展开回答：** 在真实项目里，Codex 的重点不是单次生成一段代码，而是先理解已有结构，再按项目规则做小范围改动，并通过 diff、测试或脚本验证结果。它更接近开发协作助手。

**易错点：** Codex 能执行改动不代表改动一定正确，最终仍要人工 Review。

**关联知识点：** [Codex 学习 - 基本定位](../知识点梳理/Codex学习.md#基本定位)

<a id="使用-codex-修改项目的基本流程是什么"></a>
###### 使用 Codex 修改项目的基本流程是什么

答案：

**简答：** 先明确目标和范围，再读项目规则和相关文件，随后小范围修改，最后看 diff 并运行检查。

**展开回答：** 比较稳定的流程是：说明任务目标、指定相关模块、补充限制条件、让 Codex 读取上下文、执行改动、运行项目检查、根据失败信息修正。这个流程能减少乱改文件和凭空生成内容的问题。

**易错点：** 不要只说“优化一下”或“整理一下”，这类目标太泛，容易让改动范围失控。

**关联知识点：** [Codex 学习 - 基础工作流](../知识点梳理/Codex学习.md#基础工作流)

<a id="为什么要让-codex-先读项目规则和现有代码"></a>
###### 为什么要让 Codex 先读项目规则和现有代码

答案：

**简答：** 因为项目通常有自己的目录结构、命名规则、脚本、模板和历史约定，先读上下文才能减少风格漂移。

**展开回答：** 同一个知识点在不同仓库可能放到不同模块；同一个功能在不同项目也可能使用不同架构。如果 Codex 不先读规则，很容易生成看似合理但不符合当前仓库的文件结构或代码风格。

**易错点：** 通用答案不等于项目答案，仓库现状优先级更高。

**关联知识点：** [Codex 学习 - 基础工作流](../知识点梳理/Codex学习.md#基础工作流)

<a id="prompt-里应该给-codex-哪些信息"></a>
###### Prompt 里应该给 Codex 哪些信息

答案：

**简答：** 给目标、上下文、约束和验收标准。

**展开回答：** 目标说明要做什么；上下文告诉它看哪些模块和文件；约束说明不要做什么、必须遵守什么；验收标准说明怎么判断完成，例如构建通过、检查脚本通过或 README 导航正确。

**易错点：** 只给目标不给约束，容易导致 Codex 扩大范围；只给约束不给验收，容易做完但无法判断是否真的完成。

**关联知识点：** [Codex 学习 - Prompt 写法](../知识点梳理/Codex学习.md#prompt-写法)

<a id="怎么降低-codex-生成错误代码的风险"></a>
###### 怎么降低 Codex 生成错误代码的风险

答案：

**简答：** 控制改动范围、要求依据现有代码、查看 diff、运行测试或检查，并对不确定内容标记待验证。

**展开回答：** Codex 可能误解需求、引用不存在的 API、破坏项目约定或漏掉边界条件。风险控制要靠过程：先读上下文，少量修改，检查结果，失败后根据证据修正，而不是一次性生成大段内容后直接相信。

**易错点：** 让 AI 自己说“没问题”不等于验证通过，必须看实际命令和运行结果。

**关联知识点：** [Codex 学习 - 风险控制](../知识点梳理/Codex学习.md#风险控制)

<a id="android-项目里怎么用-codex-排查问题"></a>
###### Android 项目里怎么用 Codex 排查问题

答案：

**简答：** 提供现象、日志、相关页面或模块、复现路径和期望结果，让 Codex 先定位调用链，再给排查步骤和验证命令。

**展开回答：** Android 问题常涉及 Activity、Fragment、ViewModel、Repository、Gradle、Manifest、资源和设备状态。给 Codex 的上下文越接近真实问题，输出越容易落地。排查后应通过 Gradle 编译、单测、Logcat、截图或真机复现验证。

**易错点：** 只贴一句报错不贴上下文，Codex 可能只能给通用猜测。

**关联知识点：** [Codex 学习 - Android 项目实践](../知识点梳理/Codex学习.md#android-项目实践)
