# 知识库工作流复盘

## 触发与范围

用户要求复盘工作流，或当前会话反复出现重复建文档、漏同步、解释过深、来源不足等问题时使用。普通问答无需每次复盘。依据当前会话、实际文件和检查输出；更早的经历需要读取证据后再下结论。

## 执行步骤

1. 列出具体失败：用户原要求、实际行为、影响及证据位置。先区分内容错误、教学方式、导航失效和规则冲突。
2. 找出对应入口、skill、模板或脚本，确认是缺少规则、规则互相冲突、触发条件不清，还是规则存在却未执行。
3. 对机械问题优先改进确定性检查，例如失效链接、重复锚点和漏检新文件；对判断问题改进教学或审查步骤，例如先区分类型与版本。
4. 优先修改原有权威规则或流程，避免为一次失误另建同义 skill。解释修改如何覆盖失败，同时检查是否破坏其他请求分支。
5. 用户已授权工作流调整时实施最小必要改动；只要求分析时提交建议。其他任务中发现的流程问题可报告，不擅自修改全局 skill 或扩大任务。
6. 增补 `.agents/references/workflow-acceptance.md` 中对应场景；修改脚本时运行相关回归测试。规则修改先静态核对，后续真实会话再验证效果，不混称模型行为测试通过。

## 完成条件

说明失败证据、原因、改进位置、验证结果与剩余限制。内容生成不代表用户掌握；结构测试通过也不代表教学效果已验证。学习进度和个人记忆仍只按用户明确要求更新。

方法参考：[Matt retro](https://github.com/mattpocock/skills/blob/4ae2317ddb22b046e26455e4f9c9b3aaaf62212d/skills/engineering/retro/SKILL.md)。本流程针对知识库适配，不依赖工程 issue tracker 或 PR 流程。
