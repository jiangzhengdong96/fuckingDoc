# 知识笔记维护

1. 读取 `AGENTS.md`、`docs/knowledge-rules.md` 和目标模块 README；检查工作区差异。
2. 确认请求是生成内容、补充原文、纠错还是空模板。明确生成请求直接执行，不重复询问。
3. 用标题和关键术语查重，找到现有笔记就优先修改对应章节；只有主题独立时才新建。模块按实际目录选择。
4. 新建时查看 `scripts/new-note.ps1` 的参数并使用匹配模板；更新时保留已有锚点与无关原文。
5. 讲解深度交由 knowledge-teach；版本、源码、事实争议或 GitHub 实践交由 knowledge-review。详细规则按需读取，不机械加载全部 skill。
6. 技术主题的面试结论变化时调用 interview-note-manage 维护已有问答；其他兴趣主题按用途组织。
7. 执行 knowledge-check 的验证流程，审阅最终差异。

完成条件：内容在正确的原文或新主题中；生成正文无遗留模板占位（明确要求空模板时保留骨架）；适用条件清楚；相关已有问答一致；目录与链接检查通过或明确报告既有问题。学习记录和进度只按用户要求更新。
