# 概念教学

1. 从当前问题和已有对话判断用户卡在哪；信息已足够时直接解释，不先进行目标问卷。
2. 先给结论和必要限定，再给一个最小例子。围绕同一例子按步骤说明执行者、状态、数据或引用的变化。
3. 先解释要使用的术语。抽象机制可用对照表或小图，不堆叠术语。
4. 用户说看不懂时换一种解释：短伪代码 → 分段流程 → 状态变化表 → 对应的少量源码；不要重复长调用链，也不另建同题文档。
5. 指明一个容易混淆的反例或边界。存在事实争议、版本区别、性能判断时由 knowledge-review 核实，不能用类比证明结论。
6. 只有用户希望练习或复习时，提供少量预测输出、解释原因或改错题，并根据回答反馈；普通提问不强制测验。
7. 用户要求记录时交由 knowledge-note-manage 合入原文。不要自动创建课程 HTML、学习记录或修改掌握状态。

完成条件：直接疑问有答案；例子与解释一致；伪代码标注清楚；预期和实测区分；后续解释不超过用户当前需要的深度。

方法参考：Matt 的 teach 与 wait-what；本仓库采用中文 Markdown 和原文迭代，不采用独立 HTML 课程布局。
