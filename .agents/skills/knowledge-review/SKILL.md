# 知识内容核实

1. 提取需要判断的具体结论，确认类型、版本、调用关系和适用条件；先查看相关原文，保留无关编辑。
2. 读取 `.agents/references/research.md`，优先官方文档和对应版本源码；“别人怎么做”再查 GitHub 实际调用及相关测试。
3. 对每个关键结论区分：已被资料支持、需增加条件、错误、待验证。项目实践不能替代 API 保证；源码推理不能冒充运行结果。
4. 用户只问对错时先在对话回答。请求修改时修订原位置，搜索相关摘要、示例和面试答案，修复本次结论影响的内容。
5. 引用支持该结论的具体地址和版本；无法访问时说明限制，保留待验证项。
6. 落盘后执行 knowledge-check，并报告纠正依据和检查范围。

完成条件：列出的关键结论均有判定；原文不再自相矛盾；受影响的已有问答已核对；来源可追溯。不能把链接检查通过写成内容全部正确。
